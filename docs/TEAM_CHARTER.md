## 2. 目标（三层，顺序不可颠倒）

1. **合规 1:1**：功能、菜单、页面、交互、数值、读数逻辑与原版一致；原版的广告/收费/社交直播等商业模块按"去商业"原则不实现，但要在差距矩阵里登记为"有意省略"。
2. **可工程化**：单条命令可构建、可回归；两端数值同源；无版本控制的裸目录升级为 git 仓库 + 分支流程。
3. **市场增量**：在不破坏 1:1 基线的前提下，按市场调研结论增量开发（P0 先做），增量功能必须可开关、不影响基线验收。

## 4. 协作机制

1. **任务在项目群下发**，一人一条，任务卡含：目标、验收标准、截止顺序、涉及文件。
2. **改代码前先读** `app\MECHANICS.md` 与相关源码；禁止凭记忆写数值。
3. **交付必须落盘**（仓库内文件/构建产物/截图/日志），只在聊天里说"做完了"不算交付。
4. **汇报格式**：做了什么 → 证据（命令+结果/文件路径）→ 遗留问题 → 下一步。
5. **不臆造**：任何数值、公式、行为结论必须能指向 DEX 反编译输出的类/方法/地址，或原版 APK 的可观测行为；无法证实的写"未确认"。

## 7. 当前已知风险

1. `libterrain.so` 内含 `vmInterpret`（Dalvik VM 解释器），3D 地形为 VM 保护字节码，无法静态还原 → 走"天地图 DEM + WebGL 自研等效引擎"路线，需在差距矩阵登记为"等价替代"而非 1:1。
2. `CompassToolsKt` 为深度混淆的 Compose（133 方法），逐像素圈层半径/配色抽取成本高、价值低 → 以原版运行截图逐层比对逼近，不必死抠常量。
3. 天地图 APIKEY 为内置常量：本项目为**用户自用、非商用、不上架**（见 D-001），配额按个人使用评估；不做商用授权调研，但仍需避免异常高频请求拖垮个人配额。
4. 桌面版目前只有罗盘、没有地图：**LC 的正式产品线是 Android**，桌面版定位为演示/自动验收载体（craft 检查只认桌面版），故桌面端不追求与 Android 全功能对等，但数值与读数必须一致。
5. 工程原为 craft 工作区（`craft.json`/`checks`），团队改造需保持三关不被破坏。

## 10. 技术纪律（并列生效，违反即退回）

> 本节收口「踩过一次、并且已经花了成本」的教训。每条都必须能指出事故实例；没有实例的条目不进本节。

| 编号 | 纪律 | 由来（事故实例） | 落地检查 |
|---|---|---|---|
| **T-01** | **遇到平台能力限制（fetch 被拒、canvas 污染、跨域、权限、协议限制），先查原版怎么做的，再想怎么绕。** 原版能正常用而我们不能，优先怀疑「我们走的路和原版不一样」，而不是加补丁 | M7 A 轮：`fetch` 被拒 + `texImage2D` 抛 `SecurityError`，我们先加了两次绕行（`data:` 探针、base64 内联），最后发现原版用 `WebViewAssetLoader` 走 `https://appassets.androidplatform.net/assets/`——原版从一开始就不存在这两个问题（`MapWebView.smali:181-233`） | 任何「改安全设置 / 内联数据 / 关检查」的方案，提交前必须先给一句「原版怎么做」的结论；写不出就退回取证 |
| **T-02** | **二进制文件不许过文本管道。** 禁止用 `Set-Content` / `Get-Content` / `WriteAllText` / `>` 重定向处理 png、webp、apk、db、字体等二进制 | M6：`reports/M6-stage2/drag/` 22 张 png 的签名首字节 `0x89` 被替换为 UTF-8 替换符（`EF BF BD`），文件 2.5–3.8 MB 却无法解码，全部作废（见该目录 `INVALID.md`） | 采集脚本只能 `adb exec-out screencap -p > file`（cmd 层）或二进制写；入库前跑 `evidence-lint.py`（decode 失败即 FAIL） |
| **T-02b** | **验证字节级属性（EOL、编码、magic、行数）必须按字节读源码/blob，禁止经任何文本重定向或管道。** 这是 T-02 的另一个面：文本工具改二进制，重定向改换行 | M7 B 轮实测：`git show 73955a7:docs/product/m7-b-round-spec.md` 是 8,706 B / 121 行 / CR=0；经 PowerShell `>` 写到临时文件后变 8,827 B，多出的 **121 B 正好是每行一个 CR**——差点据此误判「实现方自称 CR=0 是假的」 | 验 EOL：`git show <sha>:<path>` 取 blob 后按字节统计，或 `git diff --check`；验 magic 用 `evidence-lint.py --magic`；给实现方挑 EOL 错必须附字节数与 CR 计数，不接受「我用眼睛看是 CRLF」 |
| **T-03** | **一条根因不拆多条。** 同一根因的多个表现面合并为一条，列「表现面」而不是列条数 | M6 审计：`onPageFinished` 重放不全 + 缺幂等 set 一个根因，若按 5 个表现面拆成 5 条，清单虚高 4 条（`m6-audit-close-list.md` A 类明确「不拆」） | 审计/关账清单里每条必须能回答「根因是什么」；答不出的先归并 |
| **T-04** | **门禁要精确：宽泛的红等于没有门禁。** 只对「本次改动碰到的文件/变更集」判死，不做全仓判死；存量债单独记、专项清 | M7：`--eol` 若默认全仓判，296/699 个存量含 CR 的文件会让人一跑就红，几轮后全员开始忽略已知红 | 例：`evidence-lint.py --eol` 必须带显式文件列表，裸 `--eol` 打印 `EOL: SKIP` 并跳过 |
| **T-05** | **量形状尺寸用「该形状自己的掩膜」，不得用整体（并集）bbox 代替。** 整体 bbox 是「所有东西的外框」，不是「某个形状多大」 | M6 蓝填充量成 `47×35`、M7 定位点量成 `45×34`，两次都是把三角并进椭圆；真相是椭圆 `44×22` + 三角 `13×7` 两域分离 | 见 `docs/qa/measurement-method.md` M1；判据必须写明「按类别分连通域各自量」 |
| **T-06** | **画法会改变判据结果：按主色 bbox 判尺寸时，必须同时规定描边内/外与容差。** 不写则不同实现量出的数不可比 | M7：描边以路径为中心绘制吃掉 1.5px 主色，bbox 44→41，把本来正确的几何判成 FAIL；改外扩半个笔宽后回到 44 | 见 `measurement-method.md` M2；判据四件套：颜色+容差、描边内外、抗锯齿口径、域数与 bbox |
