## 4. 圆盘 face 的 alpha 估计

### 4.1 合成模型与取点

对半透明前景 `F` 覆盖背景 `B`：`C = αF + (1−α)B`。
- `C`：截图里圆盘内的像素（3×3 均值，避开字形/线）。
- `B`：同一角度、圆盘外 `r=520` 的像素（地图背景代理）。
- `F`：假设为暗色 `(24,20,16)`（LC 深色主题；原版 face 色未取证，故只用于给**上界**）。
- **采样避线（必读）**：红色十字线 `x=611–616`、`y=1347–1353` 是纯红 `[255,0,0]`，**不得沿这两条轴取点**；首轮沿 `y=1350` 的整行采样因此被污染、已废弃。本文圆心区样本在 45/105/165/225/285/345°，环间隙在 5/10/20/25/35/40°，均避开 0/90/180/270° 轴向。
- 以下 α 是**模型估计**（依赖 `B` 代理与 `F` 假设），不是实测值；实测事实是「中心没有变暗、绿度覆盖率 93–96%」。
- 单通道解：`α = (B−C)/(B−F)`；分母小的通道跳过；`C` 比 `B` 亮时记 0。
- 单点 `B` 代理会被地图内容（道路/阴影/文字）污染，所以**逐点 α 只能当区间，不能当精确值**；结论用 1440 角度的中位数与绿度覆盖率。

## 6. 方法、误差与复算

### 6.1 工具与命令

- Python 3（`python.exe`）+ Pillow 12.3.0 + numpy 2.3.5；无 OpenCV。
- 读图：`Image.open(...).convert("RGB")`；所有采样为 3×3 均值（`pix()`），避免单像素噪声。
- 圆心：取屏幕中心 `(614,1350)`；用红色十字线（`R>140, G<100, B<100, R−G>60, R−B>60`）复核，列 611–616 / 行 1347–1353。
- 外径：1440 角度 × r=435–470（步长 0.5），对 `G−R` 做 5 点平滑后取最大梯度点，最小二乘拟合圆；另报边界半径中位/p10/p90。
- alpha：`C` 取 3×3，`B` 取同一角度 r=520；`F=(24,20,16)`；单通道 `α=(B−C)/(B−F)`；绿度塌缩法 `α=1−(C_G−C_R)/(B_G−B_R)`。

### 6.2 误差来源（必须写进结论）

0. **红色十字线污染（最容易踩）**：`x=611–616`、`y=1347–1353` 是纯红 `[255,0,0]` 的十字线，沿 `y=1350` 或 `x=614` 采一整行会得到「全是红/极亮」的假数据（本报告首轮已因此废弃一次）。所有采样必须避开这两条轴，或至少用 1440 角度的环形采样并剔除红线像素。
1. **背景代理误差**：`B` 取圆盘外同一角度 r=520，不是同一像素的真实背景；地图内容（道路/阴影/文字）会让单点 α 在 0.00–0.92 之间乱跳，所以**只给区间/聚合**，不给单点精确值。
2. **抗锯齿/压缩**：PNG 无损，但 App 以 3.375× 渲染，线宽/字缘有 1–2 px 抗锯齿；采样避开线缘 ±3 px。
3. **圆拟合**：外缘有白刻度/数字，拟合残差 ±3 px；取 `R=450±3`、`D=900±6`，占比 ±0.5%。
4. **屏幕中心假设**：原版罗盘可能不是严格屏幕中心；红色十字线（全屏）实测交于 (614,1350)，与屏幕中心差 ≤2 px，故取屏幕中心。
5. **原版 face 色未取证**：`F=(24,20,16)` 是假设；它只用于给「暗 face 上界」，换成更亮的 F 只会让 α 上界更小，不会把 0.82 救回来。
6. **α 上界是模型估计**：`0.15` 由「B 代理 + F 假设 + 地图内容统计相似」推出，**不是实测值**；实测事实是「中心区没有变暗、绿度覆盖 93–96%」。报告/AT 引用时必须带「模型估计」四个字，不能写成「实测 α=0.15」。

### 6.3 复算脚本（可直接跑）

```python
from PIL import Image
import numpy as np
from math import cos, sin, pi
p = r"E:\APPDetector\evidence\original-apk\orig-06-read.png"
a = np.asarray(Image.open(p).convert("RGB")).astype(np.int16)
H, W, _ = a.shape
cx, cy = 614.0, 1350.0
angs = np.linspace(0, 2 * pi, 1440, endpoint=False)
def pix(r, ang):
    x = int(round(cx + r * cos(ang))); y = int(round(cy + r * sin(ang)))
    return a[y, x]
# 覆盖率 / 中位色
for r in (200, 300, 340, 350, 360, 390, 400, 440, 450, 460):
    v = np.array([pix(r, ang) for ang in angs])
    gr = v[:, 1] - v[:, 0]
    print(r, round(((v.min(axis=1) > 140)).mean() * 100, 1),
          round(((gr > 30)).mean() * 100, 1),
          round(((v.max(axis=1) < 60)).mean() * 100, 1),
          tuple(int(x) for x in np.median(v, axis=0)))
# 外缘拟合
pts = []
for ang in angs:
    rs = np.arange(435, 470, 0.5)
    xs = np.clip((cx + rs * cos(ang)).astype(int), 0, W - 1)
    ys = np.clip((cy + rs * sin(ang)).astype(int), 0, H - 1)
    gr = a[ys, xs, 1] - a[ys, xs, 0]
    gr = np.convolve(gr, np.ones(5) / 5, mode="same")
    i = int(np.argmax(np.diff(gr)[3:-3])) + 3
    pts.append((cx + rs[i] * cos(ang), cy + rs[i] * sin(ang)))
pts = np.array(pts)
A = np.c_[2 * pts[:, 0], 2 * pts[:, 1], np.ones(len(pts))]
b = pts[:, 0] ** 2 + pts[:, 1] ** 2
sol, *_ = np.linalg.lstsq(A, b, rcond=None)
ccx, ccy = sol[0], sol[1]
R = np.sqrt(sol[2] + ccx ** 2 + ccy ** 2)
print("circle", round(ccx, 1), round(ccy, 1), round(R, 1), "D/W", round(2 * R / W, 4))
# alpha 单点（示例：圆心区）
for r, ang in ((180, 45), (250, 225), (350, 5)):
    C = pix(r, ang * pi / 180); B = pix(520, ang * pi / 180)
    print(r, ang, tuple(int(x) for x in C), tuple(int(x) for x in B),
          "alphaG", round((B[1] - C[1]) / (B[1] - 20), 3))
```

> 复算要求：用同一张 PNG、同一组 `(cx,cy)=(614,1350)`；允许 ±1 px 取点差异，alpha 区间按 §4 的聚合口径判读。

## 7. 对 `CompassView` 的直接改动建议（K-01 用）

1. **删除整盘填充**：不要再 `drawCircle(cx, cy, r, bg)` 填充 `argb(210)`；圆心与环间隙必须透出地图。若要画底，只允许在文字后面画**字形描边/阴影**，不要整盘 tint；整盘 tint 是实测外的「有意差异」。
2. **半径按本表**：`R = 450/1228 = 0.3666 × 屏宽`（即直径 0.733×屏宽）；圆心 `(0.5W, 0.5H)`；24 山环 `r=318–381 px`；度环 `r=384–453 px`；轴盘 `d≈46 px`。若 `CompassView` 内部按 `r = min(cx,cy)-8f` 再内缩 8 px，则视图宽要写成 `0.733×屏宽 + 16`（客户端 step-2 的 `MainActivity` L270 即此常数），外缘才是 900–910。
3. **指针分离**：`CompassView` 自绘的红色竖线（0° 轴）与红/蓝双三角（水平指针）是两个元素；地图页的 `#needle` 是第三个元素。不要用同一个 `showPointer` 开关同时表达三者（详见 `docs/map-bridge.md` §10.3 的「指针开关（两针分离）」）。
4. **验收**：在 1228×2700 截图上量 `R` 与圆心，允许 ±2%；罗盘模式下圆心 1/3 半径内的地图纹理必须可辨认；`#controls` 不出现。

## 8. 交叉校验：45° 四射线 vs Kasa 最小二乘

2026-11-05 对同一张 `k01-04-compass2.png`（1228×2700）两法独立测量：

| 方法 | 圆心 | 外径 D | D/W | 备注 |
|---|---|---|---|---|
| 45° 四射线（地图） | `(613.0, 1349.0)` | `904.8 px` | 73.68% | 只取 45/135/225/315° 四方向，避开红色十字线 `x=611–616`、`y=1347–1353` |
| Kasa 最小二乘（客户端） | `(613.6, 1349.5)` | `907.1 px` | 73.87% | 只用金色外环像素；拟合残差 p95 `0.72–0.78 px` |

- 外径差 **2.3 px**（`907.1 − 904.8`），占 D 的 **0.25%**。
- 圆心差 **0.6 px / 0.5 px**（x/y）。
- 两法都落在判据内：外径 `900–910 px`；圆心偏差 ≤2% 屏宽（24.6 px）。
- 与原版 `orig-06-read.png` 对照：Kasa 用红色十字线法得 `(616,1352)`，与 §2 的 `(614,1350)` 差 2 px；原版外径沿用 §2 的 `900–910`。**原版不能用 45° 四射线法取值**：原版是线稿盘，45° 方向正落在透明间隙里，射线量到的是地图而不是盘缘。
- 结论：两法差 2.3 px 属方法误差（外缘像素定义不同：四射线取白边外沿，Kasa 拟合金色环），不外推为几何差异；判据以 Kasa 为主、45° 四射线为交叉校验，两法都通过。

### 9.2 代码路径：默认盘面走位图，不走矢量分支

- `MainActivity.java:949`：`int dial = prefs.getInt("dial_index", 0);` → 默认 dial 0（2026-11-05 `53327d1` 由 1 改为 0）。
- `CompassView.java:244-246`：

  ```java
      drawArtwork(canvas, cx, cy, r);

  ```
  `setArtwork(dial)` 成功解码时 `artwork != null`，矢量分支（`drawText` 等）不执行。
- `CompassView.java:239-242` 在分支前**无条件**画 2px 金色外圈：

  `drawText()` 的调用点全部在矢量分支（`else` 内）；bitmap 路径不会执行。**所以「默认盘面已加描边」不成立**，默认 dial 0 的可读性由 PNG 自带的描边决定。

### 9.3 线稿 PNG 自身的描边

对 `dial_full_0.png` 的像素统计：白字/线（alpha>200 且亮度>200）74,650 px，暗描边（alpha>120 且亮度<60）73,639 px；白像素中 **76.9%** 在 1–2 px 内存在暗像素。→ 线稿图**自带黑描边**，不是纯白字直接压地形。默认盘面切回线稿后，可读性应由 `k01-06-dial0` 的实拍截图判定（本次未上设备、未截图）。

### 9.4 结论与验收口径

1. §4 的 face α 区间（0.00–0.15，模型估计）**只对 dial 0 成立**；dial 1–4 是整圆不透明皮肤，该区间不适用。
2. dial 1–4 的**原版对照基线未取证**，验收只能写「整盘不透明皮肤」，不得写「已对齐」。
3. 默认 dial 0：判「盘内透出、地图纹理可见」；文字可读性看 PNG 自带描边 + 实拍截图。
4. 矢量回退路径（`artwork == null`）的 2px 黑描边仍保留，但它是回退路径，不计入默认盘面效果。
