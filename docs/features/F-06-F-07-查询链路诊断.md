# F-06 山脉 / F-07 水系：查询链路诊断（2026-11-05）

> 归属：LC地图。触发：客户端真机 `MountainActivity --ef lc_lat 36.25 --ef lc_lng 117.10`（泰山）与
> `WaterActivity --ef lc_lat 29.35 --ef lc_lng 112.95`（洞庭湖）均显示「没有检索到…」，而北京能出。
> 本文件记录 PC 逐段复现的原始报文与结论；修复已在 `LcHttp` 落地。

## 1 结论（先给答案）

**根因是 UA，不是省码、不是参数、不是配额。** 天地图 WAF 对非浏览器 User-Agent 直接返回 **403**；
`LcHttp` 原来写死 `User-Agent: Luopan/1.0 (Android)`，于是：

1. 逆地理 403 → `provinceCode` 返回 null；
2. 分类搜索 403 → 空；
3. 视野搜索兜底 403 → 仍空；
4. 页面落到「没有检索到」。

「北京能出」是 PC/浏览器链路（无自定义 UA）的结果，不是 App 内链路。

## 2 逐段复现（PC，2026-11-05）

### 2.1 逆地理 200，省码正确

`泰山 36.25,117.10`：

```json
{"result":{"formatted_address":"山东省泰安市泰山区泰前街道…","addressComponent":{
  "province":"山东省","province_code":"156370000","city_code":"156370900"}},
 "msg":"ok","status":"0"}
```

`洞庭湖 29.35,112.95`：

```json
{"result":{"formatted_address":"湖南省岳阳市岳阳县东洞庭湖管委会","addressComponent":{
  "province":"湖南省","province_code":"156430000","city_code":"156430600"}},
 "msg":"ok","status":"0"}
```

→ `province_code` 与预期一致（泰山 156370000、洞庭湖 156430000），排除「走错字段/返回空」。

### 2.2 省码 + 分类搜索 200，有数据

| 查询 | infocode | resultType | count |
|---|---|---|---|
| `queryType=13&dataTypes=260203&specify=156370000`（山东山） | 1000 | 1 | **117** |
| `queryType=13&dataTypes=260205&specify=156430000`（湖南湖） | 1000 | 1 | **36** |
| `queryType=13&dataTypes=260204&specify=156430000`（湖南河） | 1000 | 1 | **28012** |
| `queryType=13&dataTypes=260203&specify=156110000`（北京对照） | 1000 | 1 | 202 |

→ 省码+分类查询**没有**对这些省返回空，也**没有** `T00x` 配额/权限错误（infocode 1000 = 服务正常）。

### 2.3 UA 矩阵（同一 URL、同一参数，只改 User-Agent）

| User-Agent | 结果 |
|---|---|
| 不带 UA（PowerShell 默认） | **200**，`count=117` |
| `Mozilla/5.0 (Linux; Android 12; …) Chrome/120 … Safari/537.36` | **200**，`count=117` |
| `Luopan/1.0 (Android)`（原 `LcHttp` 写死值） | **403 Forbidden** |
| `okhttp/4.12` | **403 Forbidden** |
| `Dalvik/2.1.0 (Linux; U; Android 12; JAD-AL00 …)` | **403 Forbidden** |

→ Android `HttpURLConnection` 的默认 UA 也是 `Dalvik/…`，所以**不设 UA 同样 403**；只有浏览器形态 UA 能过。

## 3 修复

1. `LcHttp` 的 UA 改为浏览器形态（`… Chrome/120.0 Mobile Safari/537.36`），并在类注释写明「天地图 WAF 对
   Luopan/okhttp/Dalvik 返回 403」——防止以后有人把它当无用头删掉。
2. 查询顺序保持「**省码分类先、空则视野搜索兜底**」（原本就有），新增状态栏文案：
   `（省检索为空，已改用视野搜索）`，避免把「走了兜底」显示成「没数据」。
3. 已知限制不变：`dataTypes` 多值逗号会返回空（`"260204,260205"` → `count=1` 无 pois），
   所以河流、湖泊始终分两次查。

## 4 复核方式

```powershell
$k='<天地图 key>'
$q=[System.Uri]::EscapeDataString('{"queryType":13,"start":0,"count":5,"specify":"156370000","dataTypes":"260203"}')
# 403（模拟旧代码）
Invoke-WebRequest "https://api.tianditu.gov.cn/v2/search?postStr=$q&type=query&tk=$k" -Headers @{'User-Agent'='Luopan/1.0 (Android)'}
# 200 / count=117（现实现）
Invoke-WebRequest "https://api.tianditu.gov.cn/v2/search?postStr=$q&type=query&tk=$k" -Headers @{'User-Agent'='Mozilla/5.0 (Linux; Android 12; LC) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Mobile Safari/537.36'}
```
