### 3.1 直接启动为什么会「退回列表」（已定位）

`HistoryImageActivity.onCreate` 的 Intent 读取链（`mem_smali/.../HistoryImageActivity.smali`）：

| 偏移 | 指令 | 含义 |
|---|---|---|
| `#@20` | `getIntent().getStringExtra("EXTRA_GEO_POINT")` | 读 JSON |
| `#@26`–`#@32` | `const/4 v0,0` / `if-eqz v5` → `:cond_32` `move-object v5,v0` | 缺失或空串 ⇒ null |
| `#@33`–`#@38` | `if-nez v5, :cond_39` → `Activity;->finish()` + `return` | **无 extra 直接自杀**，连 toast 都不出 |

即：**不带 `EXTRA_GEO_POINT` 直启 = 秒退**，这正是窗口 2 两次「退回 `SuperMapListActivity`」的第一嫌疑。

第二条失败路径（初始化失败，同样会退回）：`o0()` → `D0()` 显示「加载中」并 `GoogleHistoryHelper.init(cb)` → 回调 `E0(activity, ok)`：`#@1` `if-eqz` 为假（ok=false）时 `#@1d` 走 `M()` 关弹窗 + `#@23` toast「获取历史影像失败，请重试」+ `#@29` `finish()`。

层级换算：`getTilesFromCenter` 取 `ceil(geoPoint.zoomLevel)` 再加 `scaleZoom(0x100)`；`scaleZoom(x) = 0x200 / x = 2`，即 **Google 瓦片层级 = ceil(zoomLevel) + 2**（>19 级时瓦片像素按 `0x100 << (level-19)` 放大）。`zoomLevel` 给小了只会取到粗层级，不会失败；失败来自上面的 extra 或 init。

### 5.0 下个窗口的启动配方（照此一次过，别再裸启）

裸启必退（见 §3.1）。正确做法是**同进程直启时把 `EXTRA_GEO_POINT` 塞进去**：

```js
// frida CLI，attach Gadget 后
var APP = 'space.xinzhi.globe';
Java.perform(function () {
  var A = Java.use(APP + '.ui.pages.HistoryImageActivity');
  Java.scheduleOnMainThread(function () {
    var ctx = Java.use('android.app.ActivityThread').currentApplication();
    var Intent = Java.use('android.content.Intent');
    var it = Intent.$new();
    it.setClassName(ctx, APP + '.ui.pages.HistoryImageActivity');
    // 取当前地图中心：latitude / longitude 用 WC84，zoomLevel 越大越细
    it.putExtra('EXTRA_GEO_POINT',
      '{"latitude":39.9042,"longitude":116.4074,"zoomLevel":12,"tilt":null}');
    ctx.startActivity(it);
  });
});
```

要点：
1. JSON 字段名 = `GeoPoint` 的私有字段名 `latitude` / `longitude` / `zoomLevel` / `tilt`（`GsonKt.toJson` 用默认 `GsonBuilder`，无 `SerializedName`、无字段命名策略，所以就是原名）。
2. 坐标要给 **WGS84**（原版调用点取 `SmartLngLat.getLngLatWgs84()`），不要直接喂 GCJ02 的罗盘坐标。
3. `zoomLevel` 建议 10–14（Google 瓦片层级 = ceil+2，即 12–16 级）。注意 `GeoPoint` 的 `latitude`/`longitude`/`zoomLevel` 都是**原始 `double` 字段**，JSON 里缺字段或写 `null` 时 Gson 会落成 `0`（不会抛错），结果是层级 2 的全球级瓦片、拿不到年份列表——所以字段一个都不能省；`tilt` 是 `Double`（装箱），可以给 `null`。
4. 若这次**出现 toast「获取历史影像失败，请重试」再退**，说明 extra 已生效、卡在 `GoogleHistoryHelper.init` 网络段，就不是 UI 直启问题了；此时一次会话里 hook `E0(activity, Boolean)` 打日志即可区分（`ok=false` 即 init 失败）。

## 6 LC 复现方案

- **开放实现**：不做 VIP 门，入口保留，功能页照做。
- 落点：`lc_history_imagery` 页：框选/中心点 + 年份时间轴 + 对比滑块 + 保存。
- 数据层：用公开历史影像源（见 §6.2），在页面上明确标注「数据源：X（非 Google Earth），分辨率/年份覆盖有限」。

## 6.1 无门槛实现方案

- 无会员/登录；不设「历史影像需会员」。
- 时间轴、对比、保存全部开放，无次数限制。
- 页面显著位置写清数据源与限制，避免让用户误以为是原版 Google 影像。

## 6.2 免费数据替代

| 原版 | 替代 | 年份/分辨率 | 说明 |
|---|---|---|---|
| Google Earth 历年影像 | **Esri World Imagery Wayback** | 2014–2024，多期 | 免费公开瓦片，最接近原版体验 |
| 同上 | **Sentinel-2（ESA）** | 2015–今，10m，5 天重访 | 免费，适合年度对比 |
| 同上 | **Landsat 8/9（USGS）** | 1984–今，30m | 长时序 |
| 同上 | 天地图历史影像 | 部分年份 | 国内覆盖好，需 key |

> 结论：**Google 历年影像不可得（无授权），不宣称等价**；「历史影像」功能完整开放，数据用 Esri Wayback（首选）+ Sentinel-2 兜底做**近似替代**，页面上必须标注数据源、年份覆盖与许可差异。
