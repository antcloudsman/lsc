## 3 记录方案（存储 / 定位 / 省电 / 续记 / 权限）

### 3.1 存储格式：**JSONL 主存，GPX 只做导出**

| 方案 | 结论 | 理由 |
|---|---|---|
| **JSONL**（每行一个点，append-only） | **选它** | ① 崩溃/断电安全：写坏一行不影响其它点，GPX 是 XML，流式追加时结束标签/结构一旦中途被杀就整份不可解析；② 追加 O(1)，不必重写整文件，省电省 IO；③ 无 schema 迁移成本，后续加点字段（`seg`/`src`）不破旧文件 |
| GPX | 只作**导出**格式 | 标准、其它地图软件可直接导入；但作为记录格式对崩溃和实时追加不友好 |

落盘（应用私有目录，不进媒体库）：

```
files/tracks/<yyyyMMdd-HHmmss>.meta.json   # 元数据 + 统计缓存
files/tracks/<yyyyMMdd-HHmmss>.jsonl       # 每行一个点
```

`meta.json` 字段：`id/startedAt/stoppedAt/status(recording|paused|finished)/lastSeq/intervalMs/minDistanceM/segments/device/stats{...}`。
`jsonl` 每行：`{"t":1699…ms,"lat":28.3637,"lng":121.0750,"acc":8.5,"spd":1.2,"seg":0,"src":"gps"}`。

- 列表页只读 `meta.json`（含四项统计缓存）→ 打开列表快；详情/回放才读 `jsonl`。
- 删除 = 删两个文件；列表页底部显示占用空间，提供「清理全部」。
- 不设条数/时长上限（自用），不写数据库（避免 schema 迁移；一天几条、1Hz 一小时约 3.6k 行/300 KB，够用）。

### 3.2 定位来源

- 主：`LocationManager.GPS_PROVIDER`（1 Hz）；辅：`NETWORK_PROVIDER`（冷启动首点、隧道/室内补点）。
- **不用** fused/GMS/HMS 与任何第三方定位 SDK（自用，避免依赖与隐私上报）。
- 点带 `acc`（水平精度）；`src` 标 gps/network，统计时统一按精度过滤，不因来源不同改公式。

### 3.3 采样与省电口径

| 场景 | 采样 | 触发条件 | 恢复 |
|---|---|---|---|
| 正常记录 | 1 s / 3 m | 默认 | — |
| 静止降频 | 5 s / 10 m | 连续 >2 min 位移 <5 m | 检测到位移即回 1 s/3 m |
| 低电降频 | 5 s / 10 m | 电量 <15%（非充电） | 充电或 >20% 回默认 |

- 降频只减少采样，**不插值、不补点**；统计按实际点算（并在 meta 记 `samplingChanges[]`，详情页可显示「含降频段」）。
- 屏幕关闭 / 锁屏继续采样（前台服务）；切 3D、切罗盘、切「更多」面板均不中断。
- 不做开机自启；进程被杀后靠「未完成轨迹」恢复（§3.4）。

### 3.4 中断与续记

- 写入：每点 append 后 `flush`；每 10 点或每 5 s 一次；停止时 `fsync`。
- 记录态：`status=recording` 落在 `meta.json`；`lastSeq` 自增。
- 进程被杀/重启：App 启动扫描 `status=recording` 的轨迹 → 列表顶部「未完成轨迹」卡（点 N / 米 M / 开始时间）；`继续`=同 `trackId` 追加（不重算历史点）、`结束保存`=按已有点结算、`丢弃`=删文件。
- 定位中断 >60 s 或用户暂停后恢复：`seg++`（分段）。**统计不跨段累加、回放不跨段连线**（避免出现「直线穿越山体」的假轨迹）。
- 飞行模式/无信号：不清空、不重算，恢复后按新段继续。

### 3.5 权限（自用可接受，均为记录必需）

| 权限 | 用途 | 说明 |
|---|---|---|
| `ACCESS_FINE_LOCATION`（连带 COARSE） | 采样 | 拒绝时：可进列表，`开始记录`置灰并说明「需要精确位置」；**不**静默降级成网络定位 |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_LOCATION` | 锁屏继续记录 | API 34 必须声明类型；服务在 App 前台时启动 |
| `POST_NOTIFICATIONS`（API 33+） | 前台服务常驻通知 | 拒绝时仍可记录，但需在设置面板提示「通知被关，锁屏可能被系统回收」 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 华为等机型保活 | **只引导跳转，不强制**；不申请「始终允许后台定位」（用前台服务即可，少一个持续定位门） |

前台服务通知文案：`正在记录轨迹 · 1.23 km · 00:12:34`，点击回列表。

## 4 四项统计：算法映射与验收

输入点集 `p_i = (t_i, lat_i, lng_i, acc_i, spd_i, seg_i)`，按段处理。

### 4.1 预处理（漂移过滤）

| 规则 | 参数 | 处理 |
|---|---|---|
| 精度过滤 | `acc > 30 m` | 丢弃该点（不参与统计/回放） |
| 重复时间 | `dt ≤ 0` | 丢弃后点 |
| 跳点 | `d/dt > 40 m/s`（144 km/h） | 断段（`seg` 视为变化），该段不计入里程/速度 |
| 长间隔 | `dt > 120 s` | 断段，不累加跨段距离 |
| 静止 | `d < 0.5 m` 且 `dt ≥ 1 s` | 不计里程（防抖），仍参与用时的停顿判定 |

### 4.2 四项定义（唯一口径）

| 统计项 | 算法 | 分母/边界 |
|---|---|---|
| **总里程** `L` | 同段相邻有效点 Haversine 累加（R=6371008.8 m）：`L = Σ 2R·asin(√(sin²(Δφ/2)+cosφ₁cosφ₂sin²(Δλ/2)))` | 跨段/跳点/长间隔不计；<2 点 = 0 |
| **总用时** `T` | 记录时长减去停顿：先算每段 `T_s = t_last − t_first`；**停顿** = 该段内连续 ≥60 s 且窗口速度 <0.5 m/s 的区间，整段剔除 | `T = Σ T_s`；若全程静止 `T=0`（显示 `00:00:00`） |
| **平均速度** | `v̄ = L / T`（km/h） | **分母 = 运动时间 T（已剔停顿）**；详情页另给「含停顿总时长」与「总均速=L/记录时长」，并注明四项用的是运动口径；`T=0` 显示 `—` |
| **最高速度** | 中心差分平滑：`v_i = d(p_{i−1},p_{i+1}) / (t_{i+1}−t_{i−1})`（窗口 ≥2 s；邻点太近则向两侧扩到 ≥2 s）；取 `max`，且峰值需在相邻窗口保持（相对差 ≤10%），否则取次高稳定值 | 跨段窗口不参与；有效点 <3 显示 `—` |

**为什么最高速度要平滑**：1 Hz GPS 的单点速度抖动常出现「步行 12 km/h」的假峰；中心差分 + 稳定性要求把单点尖峰压掉，代价是极短冲刺（<2 s）会被低估——自用可接受，且比虚高可信。

### 4.3 验收判据（真机 200 m 轨迹，四项误差 <2%）

前置：`docs/qa/` 下脚本 `track_stats.py`（由 JSONL 复算四项）与真机同一份点集。

1. **算法一致性（强判据）**：同一份 JSONL，脚本复算的四项与 App 显示逐位一致（浮点按显示精度，容差 0）——防止两端出现第二套公式。
2. **200 m 直道**（跑道/皮尺标定，匀速走或跑，秒表计总时长 `t`）：
   - 里程：`|L − 200| / 200 < 2%`；
   - 用时：`|T − t| / t < 2%`（匀速无停顿，`T` 应≈`t`）；
   - 平均速度：`|L/T − 200/t| / (200/t) < 2%`。
3. **最高速度（弱判据）**：匀速前提下 `|v_max − v̄| / v̄ < 2%`；超差记 finding（GPS 抖动），报告中必须附 `v_max`、`v̄` 与原始点速度序列，不单独判失败。
4. **静止不计时**：站定 5 min，`T` 增长 <5 s。
5. **断段**：飞行模式 2 min 再恢复 → `segments=2`，里程不出现跨越中断的直线距离（与人工两点距离对比）。

> 200 m 场景不足以标定最高速度，这是物理限制；用「算法一致性 + 匀速近似」双判据兜住，不把虚高的单点速度当通过。

## 5 回放：不做视频，改地图内动画

### 5.1 取舍（这是产品决定，不是实现选择）

原版回放是**视频合成**（`正在保存视频`、视频权限、视频分享）。LC **不做**：

- 不做视频合成、不录屏（MediaProjection）、不加水印、不做视频分享；
- 原版「正在保存视频 / 未授予视频权限」整条链路不复刻。

理由：视频链路要处理编码兼容、权限、水印、分享目标，成本 1.5–2 人日且收益低（自用看轨迹要在图上看，不是发视频）；把这笔预算换成「动画回放 + GPX 导出」，自用价值更高。

### 5.2 动画回放（LC 实现）

- 轨迹折线按速度 5 档着色（§2.3）；播放光标沿轨迹移动（圆点 + 方向箭头）。
- 时间轴：Slider 0…T 拖动（暂停态可拖，拖动即预览该时刻）；播放/暂停；倍速 1×/2×/4×/8×（按时间插值，不跳点）。
- 顶部浮层显示：`已走 1.23 km · 用时 00:12:34 · 当前 8.2 km/h`。
- 跟随：默认开（地图中心跟随光标），可关（手动看全貌）。
- 跨段：回放到分段处暂停 0.3 s 再继续，不画跨段连线。

### 5.3 地图接口（缺口，交 LC地图）

`map.html` 现有接口不含轨迹绘制，需新增（命名沿用 `lc_*`）：

| 方法 | 入参 | 行为 |
|---|---|---|
| `lc_track_load(json)` | `[{lat,lng,t,v,seg}]` | 载入轨迹，绘折线（按 v 着色） |
| `lc_track_progress(u)` | `0…1` | 更新已绘段与光标位置（按时间插值） |
| `lc_track_follow(on)` | bool | 地图中心是否跟随光标 |
| `lc_track_clear()` | — | 清除轨迹与光标 |

桥未就绪时：回放页照开，显示「轨迹回放需要地图支持（待接入）」，**列表/详情/导出不受影响**（不锁功能、不提示开通）。

### 5.4 与原版的差异（如实登记）

| 能力 | 原版 | LC | 登记 |
|---|---|---|---|
| 回放 | 视频合成 + 分享 | 地图内动画回放 | **有意差异**（不做视频导出） |
| 视频水印「三维山水用户」 | 有 | 无 | 不做 |
| 轨迹导出 | 未确认（视频分享为主） | **导出 GPX**（可导入其它地图软件） | 替代能力 |
| 四项统计 | 有 | 有，口径见 §4 | 1:1 |
| 列表/详情/删除 | 有 | 有 | 1:1 |

GPX 导出：标准 GPX 1.1（`trk/trkseg/trkpt@lat@lng` + `<time>` ISO8601 UTC，按 `seg` 分 `trkseg`，不写 `<ele>` 除非记录时已有高程）；写 `Documents/LC/tracks/<yyyyMMdd-HHmmss>.gpx`（MediaStore），并提供系统分享。

## 6 无门槛文案（验收会直接判缺陷）

**禁词**（全页面、含 toast/空态/按钮）：会员 / VIP / 专享 / 开通 / 升级 / 试用 / 试看 / 解锁 / 付费 / 订阅 / 去水印 / 购买。

| 场景 | 文案 |
|---|---|
| 列表空态 | `还没有轨迹。点「开始记录」，走一段就会在这里出现。` |
| 权限说明 | `记录轨迹需要精确位置权限。轨迹只保存在本机，不会上传。` |
| 后台引导 | `允许后台运行，锁屏后也能继续记录。`（按钮 `去设置`） |
| 通知被关 | `通知被关闭，锁屏时系统可能提前结束记录。` |
| 停止 | `停止并保存` / `继续记录` / `结束保存` / `丢弃`（丢弃二次确认：`丢弃后这段轨迹不可恢复。`） |
| 导出 | `导出 GPX（可导入其它地图软件）` |
| 回放 | `回放` / `倍速` / `跟随` / `回放结束` |
| 删除 | `删除后不可恢复，只删除本机文件。` |
| 数据不可得 | 回放桥缺失：`轨迹回放需要地图支持（待接入）`，不写「会员可用」 |

页面任何位置不出现价格、皇冠、锁、VIP 角标、模糊预览、次数/时长限制。

## 9 工作量与风险

| 模块 | 粗估 | 归属 |
|---|---|---|
| 前台服务 + 自适应采样 + 权限/保活引导 | 2 d | LC客户端 |
| JSONL 存储 + 未完成恢复 + 分段 | 1 d | LC客户端 |

| GPX 导出 + 分享 | 0.5 d | LC客户端 |
| 地图桥 `lc_track_*` | 1–1.5 d | LC地图 |
| 合计 | **约 7.5 人日 + 桥 1–1.5 人日** | — |

**风险**

1. **华为后台保活**：白名单引导后仍可能被省电策略杀；需真机长测（≥30 min 锁屏），失败时退到「每 5 min 落一次点 + 未完成恢复」，不能静默丢整段。
2. **GPS 抖动**：1 Hz 下最高速度天然不稳；已用平滑 + 弱判据处理，报告里必须给原始速度序列。
3. **室内/隧道**：`acc>30 m` 过滤会丢点，表现为里程偏短（不虚高）；分段标记避免假直线。
4. **回放依赖地图桥**：桥未就绪时回放页只占位，不算功能缺失（不锁）。
5. **与 K-01 交叉**：入口在「更多」16 宫格，需 K-01 单页面板就绪；若面板未上线，先用现有 stub 入口，不额外造导航。
6. **原版截图缺失**：轨迹三页真机截图未采（F-15-轨迹.md §5），控件尺寸/配色待补；本文的验收只依赖功能与数据，不依赖像素还原。
