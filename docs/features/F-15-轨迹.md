### 3.1 采样与脏点过滤策略（`TrackPointQualityPolicy`，静态已取到）

`manager/track/TrackPointQualityPolicy.smali` 顶部的具名常量（全部 `private static final`，可直接当规格用）：

| 常量 | 值 | 含义 |
|---|---|---|
| `ABNORMAL_ACCURACY_METERS` | `300.0f` | 精度差于 300 m 直接判异常点 |
| `PRECISE_JUMP_ACCURACY_METERS` | `25.0f` | 精度好于此值时启用跳点倍率判定 |
| `JUMP_SPEED_MULTIPLIER` | `2.5`（double） | 速度突变阈值 = 正常速度 × 2.5 |
| `ACCEPT_QUALITY_SCORE` | `0x3c` = **60** | 质量分 ≥60 接受 |
| `WEAK_QUALITY_SCORE` | `0x2d` = **45** | 低于此分判弱质量 |
| `RECOVERY_BAD_POINT_COUNT` | `3` | 连续 3 个坏点后进入恢复 |
| `RECOVERY_BAD_POINT_DURATION_MS` | `0x7530` = **30000 ms（30 s）** | 恢复窗口 |
| `TRUSTED_HIGH/NORMAL/LOW/BAD` | `1/2/3/4` | 可信度分级 |
| `GPS_SIGNAL_GOOD/BAD` | `1/0` | 信号分级 |
| `LOCATION_TYPE_GPS/WIFI/CELL/COARSE` | `1/5/6/11` | 对应 `LocationManager` 的 provider 类型码 |

即原版**不是来点即存**：按精度 + 速度突变 + 质量分过滤，连续 3 个坏点、30 s 后走恢复逻辑。

> 「采样间隔」仍未闭合：`TrackManager` 里没有 `LocationRequest`/`setInterval` 调用，请求参数应该在定位管理器/服务侧，不在 TrackManager。客户端做 1:1 时按「不比这组阈值更松」实现即可，具体 interval 需真机或继续追 `LocationManager` 调用点。

### 5.0 窗口启动配方（已静态确认，窗口内一次过）

三个页面的启动器与参数（`ui/pages/track/*$a.smali`）：

| 页面 | 启动器 | 参数 |
|---|---|---|
| `TrackListActivity` | `TrackListActivity$a.a(Context)` | **无参数、无 extra**（启动即列表） |
| `TrackSettingActivity` | `TrackSettingActivity$a.a(Context)` | **无参数、无 extra** |
| `TrackReplayVideoActivity` | `TrackReplayVideoActivity$a.a(Context, int trackId, String videoUrl, String trackName, String avatar, String nickname, String trackTime, String from)` | extras：`extra_track_id`(int) / `extra_video_url` / `extra_track_name` / `extra_avatar` / `extra_nickname` / `extra_track_time` / `extra_from` |

回放页**不需要**每个 extra 都给：`onCreate`（@#@7–@#@45）缺 `extra_video_url` 落成 `""`、`extra_track_name` 为空时标题回落 **`轨迹回放`**、`extra_track_id` 缺省 `0`，**不会因此 finish**。所以窗口内可以裸启回放页拿「播放器壳 + 标题」这一屏（视频区是空的，这是原版在无 URL 时的真实表现，属可接受证据）。

推荐顺序（20 分钟 4 张）：
1. `TrackListActivity`（列表 / 空态）
2. `TrackSettingActivity`（权限设置页，重点四行状态文案）
3. `TrackReplayVideoActivity`（裸启，标题 `轨迹回放`）
4. 回列表页点某项进「历史轨迹详情」（列表为空则记录空态文案并跳过）

直启复用 `docs/features/tools/probe-launch.template.js`，换 `setClassName` 即可；这两个页**没有 VIP 分支**，不需要 `isVip` 钩子。

**窗口前的预期管理（静态已确认）**：
- 轨迹列表**读本地 SQLite**（`TrackManager$getTrackList$1` → `TrackDbHelper.getTrackByRemoteId/createTrack/updateTrack/replaceTrackDetail`，分页 `getTrackListForPage`），**不强制登录**；
- 因此 gadget 全新安装、没有录制过轨迹时，列表页会直接进**空态**，原文 **`暂无历史轨迹记录`**（`TrackListActivity$p$c.smali:675`）；
- 空列表意味着「历史轨迹详情」进不去（没有条目可点），窗口内就按空态交图并记录该文案，不要为凑详情页去造一条假轨迹。


## 6 LC 复现方案

- 落点：「更多 → 轨迹记录」→ `lc_track_list`；记录态在 `MainActivity` 内（FGS + 通知）。
- 记录：前台服务 `LocationService`（`FOREGROUND_SERVICE_LOCATION`），采样默认 **1s / 5m**（可设），落本地 SQLite（`tracks` 表 + `points` 表）。
- 列表：显示 总里程/总用时/平均速度/最高速度/日期；项操作 查看/删除。
- 回放：地图折线动画 + 速度着色；**视频导出**用 `MediaProjection` 录屏或逐帧合成（MP4）。
- 设置页：后台保活引导（电池优化白名单）、通知权限、采样间隔、精度。
- 开关：`lc_feature_track`。

## 6.1 无门槛实现方案

- 无会员/登录；记录、查看、导出视频全开放。
- 不限制轨迹条数/时长；不做「会员去水印」——水印默认关闭或可关。
