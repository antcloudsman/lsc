## 2. 严重度分级（判定顺序：先结构/功能，再布局/样式，最后细节）

| 级别 | 定义 | 判定要点 | 典型例子（来自第一轮已取证事实） |
|---|---|---|---|
| **P0** | 结构、功能、业务逻辑不符 | 页面层级/导航模型不同；功能缺失或行为相反；业务规则（付费/权限/数据）不同 | 原版**单页全屏地图 + 罗盘浮层**，LC 是底部三 Tab 互斥整页（bugs.md K-01，证据 `a407d41`）；原版点「罗盘」不换页，LC 换页；原版地图页底部显示「数据来自世纪空间 审图号:…」，LC 缺该信息条 |
| **P1** | 布局/按钮/模块/样式/效果明显差异 | 控件位置/尺寸/数量不同；整块模块缺失或多余；主色/字体/动效明显不同 | 左列 8 工具、右列 10 控件在 LC 缺失或位置不同；「更多」bottom sheet 16 宫格未实现；盘面按钮高 97 vs 原版行高 157；选中色 hex 明显不同（ΔE>3） |
| **P2** | 细节 | 单点像素级偏差、文案标点、间距、非主色微差 | 文案「截屏」vs「截图」；圆角差 1–2px；同一状态色 ΔE 1–3；图标线宽差 1px |
| **DI** | 有意差异 | 已由决策记录（D-00x）授权，**不是缺陷**，不计入还原度 | 去广告/去会员墙（D-006）；默认图源由世纪空间改天地图（D-006/T-13）；付费墙解除（T-15）；记录库未做（T-16，增量不属 1:1） |
| **NC** | 不可比 | 原版页面/状态无法进入、依赖付费/云端/会员，或证据不足 | 原版会员功能页（vip 拦截）；需云端任务的功能态；原版页面 finish 无法截图（如 HistoryImageActivity 直启退回） |

**升级/降级规则**

1. 同一差异导致用户**无法完成原版能完成的动作** → 至少 P0（例：无法进入读盘弹层）。
2. 差异只影响**观感/对齐**、不影响动作 → P1（布局/样式）或 P2（细节）。
3. 若差异是决策记录明确授权的 → **DI**，即使视觉差异很大也不计分。
4. 一条记录内混合多种差异时，`sev` 取最高级，`diff_type` 列全，`notes` 写清拆分。
5. P0/P1 必须给出**量化值**（px/hex/ΔE/sp/文案）；给不出 → 降为 `待补`，不得写「明显不同」。

## 3. 量化方法（统一算法，避免各人各算）

### 3.1 位置与尺寸（px）

- 基准：屏幕左上角为 (0,0)，取自 dump 的 `bounds`；截图量取用同一坐标。
- `delta = orig - lc`（x/y/w/h 分别算），正负号保留；报告写「原版−LC」。
- 容差：`|delta| ≤ 2px` 记 P2；`>2px 且影响对齐/可点性` 记 P1；控件整体缺失记 P1（结构缺失记 P0）。
- 多控件页面给「控件表」而不是只给一张图：名称、原版 bounds、LC bounds、delta。

### 3.2 颜色（hex + ΔE2000）

- 取色点：控件纯色区中心 5×5 像素平均，记录采样坐标 `(x,y)`。
- 记录 `#RRGGBB`，并用 CIEDE2000 算 `ΔE`；阈值：`ΔE ≤1` 视觉一致（P2 或不记），`1<ΔE≤3` P2，`ΔE>3` P1。
- 背景/文字/按钮/选中态各至少一处；渐变只取两端与中点并注明。

### 3.3 字号与文案（sp + 逐字）

- 优先取 dump 的文本与控件高度；dump 无 sp 时，用「字形像素高 ÷ 设备 density」估算并注明 `sp_est`，误差 ±0.5sp。
- 文案比较逐字（含全角/半角、空格、标点、U+200C）；差异用 `diff` 形式记录「原版 → LC」。
- 文案差异默认 P2；若改变含义/误导（如「已核对」类声明）→ P1。

### 3.4 动效与交互

- 记录 `action → 结果`、触发方式（点击/长按/双击/滑动）、时长 ms（录屏关键帧或日志时间戳）。
- 无动效写 `none`，不要留空；「有动效但未测时长」记 `待补`。

## 5. 可复核性硬门槛（5 条，缺一不可）

1. **入口可复现**：`entry_path` 能照着点到（坐标或文案选择器），不接受「在设置里」这类模糊描述。
2. **命令可复现**：`repro` 给出 adb/uiautomator 命令或点击序列，第三人可原样执行。
3. **证据有指纹**：截图/dump 有路径 + sha256，且属于声明的包与状态。
4. **量化有单位**：px/hex/ΔE/sp/ms/逐字，任一差异必须带单位与算法。
5. **构建来源可核（schema 已定死，2026-11-06）**：LC 侧 `meta.build.branch="develop"`（默认）、`build.commit=<40 hex>`、`apk.sha256=<hex>`、`apk.bytes=<int>`。**缺 `build.commit` 时工具必须报错退出**，不得静默写空；缺任一字段 → 整批证据作废（`待定级`）。

> 不满足 1–5 的发现：写入「待补」区或标 `待定级`，**不得**进 `findings` 正式表，也不得进 Stage 5 计划。

**已发生的反例（2026-11-06，`cd47703`）**：LC 侧 `compass-main-01` 从 `fix-p0` 分支构建（该分支缺 96 个 `app/` 文件、13,636 行，`strings_gap/weather/overlay/mountain…` 为空），截图整屏黑底、盘面/底图未渲染，`logcat` 无 FATAL；`meta` 里也没有 `build.commit`。处置：**现象挂「待定级（构建来源无效）」、不进差异清单**；用 `develop` 重建后同名重采，并在提交信息里写「证据作废原因」。
