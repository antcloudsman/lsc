# 坐标顺序取证（A-12 / R2-025 观察项）

结论：**原版一律「经度,纬度」（lon,lat）**，分隔符是**全角逗号 `，`**；搜索框输入也要求经度在前
（`116.4074,39.9042` 能出结果，`39.9042,116.4074` 无结果）。

## 1. dump 统计（`docs/fidelity/orig/*.xml`，全部原版态）

脚本口径：正则 `^(-?\d{2,3}\.\d{3,})\s*[，,]\s*(-?\d{1,2}\.\d{3,})$`，命中后按数值范围判序
（经度 ∈ [73,136]、纬度 ∈ [3,54]）。

- 命中 **131** 处，全部满足「第一值 100~122、第二值 28~40」→ **lon,lat**，无一例反序。
- 样例（同一固定态 `116.4074，39.9042`，5 个节点是同一条文本的嵌套 span）：

| 文件 | 文本 | bounds |

## 2. 搜索输入的顺序要求

R2-025 观察记录：`116.4074,39.9042` 返回 GCJ02/WGS84/BD09/CGCS2000 四行；`39.9042,116.4074` 无结果
——原版把第一个数当经度解析，不猜。

## 3. 对 LC 的落点

- 列表/坐标条/搜索结果统一 `经度,纬度`，分隔符用全角 `，`（与 R2-026 判据「文案 + 全角逗号」一致）。
- 搜索解析按「第一值=经度」实现，不做「先试纬度再试经度」的自动纠正——那会与原版行为不一致。
