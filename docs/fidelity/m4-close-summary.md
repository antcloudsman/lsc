## 5. 判据「空真」检查清单（新纪律，总监 2026-11-07 立）

> **空真（vacuous truth）和假证据是两种病，但都会让关账变成假的。** 任何 PASS 都要先问一句：**这个 PASS 是真跑出来的，还是因为没触发才没失败？**

拿到任何「通过」先过五问：

| # | 检查 | 今天的实例 |
|---|---|---|
| 1 | **触发条件真的发生过吗** | `PIN_IN_LOG=False`：S3 BLOCKED、从未出现认证对话框、没注入过 PIN → **空真**，只能记「S3 未覆盖」，不许写「脱敏已验证」 |
| 2 | **被验证的路径真的走过吗（还是走了降级分支）** | `has-plaintext-token=False`：必须先确认 **Keystore 路径真的成功**，而不是走了「Keystore 不可用 → 不持久化」的降级分支得出「无明文」 |
| 3 | **节点存在 ≠ 文案达标** | 早前 R2-006：`reading_text` 节点在、但文案不对；判据只认逐字 |
| 4 | **行为对 ≠ 内容对** | 点得开 ≠ 打开的是对的页/对的文案；F 类判据必须同时看目标与内容 |
| 5 | **计数增加 ≠ 这条记录是我造的** | 反馈闭环不能只看 `feedback 8→9`，要看**字段逐字**能对上本次输入（`e64-reason`/`e64@example.com`/`e64-desc`），且最好有第二条独立记录（`form@example.com` 那条）互证 |

**落地要求**：报告与摘要里凡写「通过」，必须能回答这五问中的对应一条；回答不了就写「未覆盖 / 未验证」，**不许写通过**。
