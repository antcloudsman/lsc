### 1.2 服务端 v2 实现事实（`d7d0062`，合入 develop；`api.md` 已收「v2 定稿」）

- 迁移 `001_init → 005_legacy_user_id` 幂等，**v1 旧卷直接升级**（原 `cases=2` 原样保留）。
- 账号链路：注册 / 登录 / 登出 / `logout-all` / 改密 / 会话列表与撤销 / `me`；密码 **`scrypt N=32768,r=8,p=1` + `timingSafeEqual`**；**token 32B 随机，库内只存 `sha256(token+pepper)`**，`/data/.token-pepper` 权限 `0600`（44B）。
- 收藏点按原版 `CollectPointModel` **13 字段**；`userId` 由 token 覆盖（客户端传 999999 被忽略）；`since` 增量 + `cursor`，`rev` 乐观锁 409 带服务端快照，软删除不复活（404）。
- 反馈 `type:int` **只落 2**，其它 400 标「原版值域未取证」；`Idempotency-Key` 幂等。
- `/v1/*` 全量 **410**；CORS 白名单精确匹配；日志只记 pathname（脱敏）。
- 限流：**IP 级登录 60/分、注册 100/时；每用户 5/分不变**（上调原因：自检连跑第 5 轮会被自己限成 429）。
- 响应形状：列表 `data{items,count,cursor}`；越权访问 B 看不到 A 的列表、改/删 A 的 id → **404**（不泄露 id 存在性，拒绝效果等同 403）。
- `user.uid` **数值化对外**（原版 `userId` 是 Long），文本 `user_…` 只作鉴权——**标【我方新增】**。
- 容器内自检 **`SELFCHECK: PASS (68 checks)`**，连跑两轮 exit 0；持久化实测同一行 `id=18 / rev=44` 重启后仍在，重启前 token 仍可用。

## 3. 本轮业务闭环验收路径（注册 → 登录 → 收藏 → 拉回 → 反馈 → 登出）

**环境前置（每步都成立）**：容器 `docker compose up -d` 且 `/health` 200；真机先 `adb reverse tcp:8787 tcp:8787`（服务只绑宿主机 `127.0.0.1`，不反向设备连的是自己）；装包后 `pm path` 记 base.apk size/sha。

> 每一步都要「客户端截图 + dump + 服务端日志/DB 抽样」三件；实现方不自签，由 LC审核验 执行。

## 4. 安全红线 → 验收检查项（与 §2.3 M4-08 对应）

### 4.1 引用纪律（团队规范，总监 2026-11-07 采纳审核验 §24.4）

- **`map.html` 是 APK 内资产、注释会进产物**：证据 meta 写 `commit=1ad400d` 时，引用必须写「**`1ad400d` 构建的 `8,565,452 B / 9928856C…` / 517 条目**」，**不能**写「develop 版 APK sha」——`d53d4bc` 含 `b965676` 的注释修正，自建 APK 不会是这个哈希。
- 反过来，剔除注释逐行比对 **2719 行相同、语义零变化** 的结论成立；但**资产文件含注释时，证据与代码的对应关系除 commit 外必须带构建体指纹**（五项指纹口径）。
- 后续凡是**采完证据**的提交，**立刻合进 develop**，不留分支等（R2-027 双图滞留分支导致审核验判不了的教训）。

| # | 红线 | 验收检查（可复现） |
|---|---|---|
| 1 | 密码哈希 | DB 抽样 `users.password_hash` 前缀为 scrypt 标识；`grep -ri "password" backend/src` 无明文比较；禁 `md5/sha1/base64` |
