# M6 Stage 4 · 帮助中心成文校对基线（清单）

> 建立：2026-11-08　｜　成文：LC审成文　｜　适用：Stage 4「帮助中心带图操作文档（第 5 条）」
> 用法：@LC产品 的大纲与 @LC客户端 的入口落地后，按本文四问逐节打勾；插图一律先过 `evidence-lint.py`。
> 本文只定「怎么校」，不预先写正文——正文由产品出，我这里不代写。

## 1 先钉三条事实（避免文档写错方向）

| 事实 | 出处 | 对成文的要求 |
|---|---|---|
| **原版帮助中心是远端 WebView**（在线帮助，正文不在 APK 内） | `M3PageActivity.java:28`（原版 WebView 远端 URL）、`:87`（`ApiHelper.HELP_CENTER`，yuque 组织 wiki）、`:81`（原版在线、离线无法加载正文，`D-023`） | 不写「原版离线可读」；正文说明这是**我方自写**内容 |
| 原版 `help.xml` 只有标题一个节点，正文在 WebView 内 | `docs/fidelity/m3/help.xml`（标题 `[506,154][722,233]`，无正文节点） | 插图若拍 WebView 正文，需声明「正文以我方页面为准，非原版对照」 |
| 「离线可读」是我方改进项 | 技术总监 2026-11-08 裁定；`help-offline.xml` 47 B 垃圾已作废（见 `docs/fidelity/evidence-lint.md`） | 写进「我方改进」段，**不计入 1:1 判据** |

## 2 校对四问（每节逐条打勾）

1. **结构**：目录 → 节标题 → 正文 → 图；每节一个功能，不合并、不拆碎（一节 = 一个能点开的入口）。
2. **术语一致**：全文同一功能只有一个名字（见 §3 词表），标题与正文、图注、目录三处用词必须相同。
3. **不描述未实现功能**：§4 清单里的项目，只能出现在「已知限制」或「我方改进」段落，**正文里不许出现「可以…/支持…」的表述**。
4. **插图与正文对应**：每节至少一图，图注写明「页面 + 操作 + 冻结状态」；正文提到的控件在图上必须能指出来。

## 4 禁止写成「有」的清单（只能进「已知限制」/「我方改进」）

| 项 | 状态 | 依据 |
|---|---|---|
| 当前位置符号、屏幕中心符号 | **未取证**（原版 web 层 `userLocation`/`locationMarker`/`geolocate` 零命中） | M6 Stage 2 结论；挂起中 |
| 罗盘贴地（盘面铺到 3D 地形上） | **未实现** | 技术总监：A 路线方案批了未动工；不得写「已实现」 |

| 离线可读 | **我方改进** | 见 §1 |

## 5 插图规范与 lint

- 命名：`help-<section>-<nn>.png`（如 `help-compass-01.png`），与正文节一一对应；状态写进图注，不进文件名。
- 规格：1228×2700、动画三项 0、同状态（罗盘 heading 冻结 0°、地图 39.9042/116.4074 z=12）。
- **入库前必过 lint**（这是我在 Stage 4 的硬动作）：

```bash
python tools/fidelity/evidence-lint.py --root <插图目录> --expect-size 1228x2700 \
  --allow tools/fidelity/evidence-lint-allow.json
# 要求：fail=0；warn 逐条看；allowed 仅限清单内条目
```

- 每图配：截图 + （能 dump 的）dump + 一句「这一刻是什么状态」。WebView 正文内部 dump 不可见时，写「截图-only + 原因」。
- 图不能是纯色/空屏、不能是 0 字节、不能尺寸不符（lint 会拦，别指望人工眼看）。

## 6 通过判据（Stage 4 我签字的口径）

1. 目录列出的每个功能，在 App 中**真实可点开**（一条路径 + 坐标或菜单路径）；
2. 每节正文与图对应，术语按 §3；
3. §4 清单里没有任何一项被写成「已支持」；
4. 插图 lint `fail=0`，且每张图在图注里写明状态；
5. 「离线可读」出现在「我方改进」而非 1:1 正文。

> 任一条不满足，我按缺陷退回产品改稿，不代改。
