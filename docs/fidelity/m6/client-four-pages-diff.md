### 0.2 我方数值来源与校验

我方四页全部由 `M3PageActivity.java` **纯代码构建**（`res/layout/` 下只有 `activity_main.xml`，四页无 layout 文件）。

**关键口径（本表最重要的一条前提）**：`View.setPadding(a,b,c,d)` 与 `new LinearLayout.LayoutParams(120,120)` 的单位是**像素**，不是 dp。四页所有 padding 都是小整数（20/24/16/12/32），在 density=3.375 的机器上等于原版视觉的 **1/3 左右**。而 `setTextSize(17f)` 默认是 sp（=57.4px）。

校验锚点（第四轮实测，`docs/fidelity/m3/stage3/README.md:30`）：

```
lc_m3_avatar_img=[20,376][140,496]
→ x=20  = list.setPadding(20,0,20,32) 的 20px
→ 宽 120 = LayoutParams(120,120) 的 120px（不是 120dp=405px）
```

本表推算「头像顶 y=375」，实测 376，**误差 1px**，故同一推算方法可用于其余项。

## 1. 结构差异（比像素差异大，先定这个）

### 1.1 联系我们：原版是**对话框**，我方是**整页**

- 原版证据（`docs/fidelity/m3/contact.png`，实图）：白色圆角 **Dialog** 浮在抽屉之上，含标题 `邮箱地址`、正文 `account@xinzhi.space`、蓝色圆角按钮 `复制邮箱`、右上 `×`。左侧仍可见抽屉「地图设置/账户设置/…」，右侧地图可见。
- dump 佐证：`m3/contact.xml` **没有 `返回` 节点、没有标题栏节点**，三行文案 bounds 全在屏幕中下部（`邮箱地址 [506,1199][722,1278]`）——整页页面不会是这个形态。
- 我方现状：`M3PageActivity.buildContact()`（`:684-716`）把三行塞进 `ScrollView`，页面仍是**整页**（顶栏「返回 + 联系我们」+ 正文），由抽屉入口 `startActivity` 打开。
- 结论：**载体不同源**（Dialog vs Activity）。1:1 不能靠调 padding 达成，需要改成 `Dialog`/`DialogFragment`。这不属于「排版微调」，应单列。

### 1.2 账户设置：原版是**设置列表**（分隔线 + 右侧 chevron + 底部红按钮），我方是**文本流**

- 原版（`m3/account-setting.png`）：白卡片、每行一条 1px 分隔线、行右侧 `›` chevron、`去绑定` 蓝色、底部**红底圆角整宽按钮「退出登录」**（红 `(233,59,77)` 占 4.2% 面积）。
- 我方（`M3PageActivity.buildAccount()` `:422-547`）：全部 `TextView` 竖排，无分隔线、无 chevron、无按钮背景；`退出登录` 是红色**文字**（`Color.rgb(220,120,100)`，`:543`），不贴底。
- 已登录态的内容构成（昵称/账号/修改密码/同步收藏点/退出登录）是 **M4 自建、非原版**（产品 §5-6 已定不按 1:1 判），但**行高、左内缩、分隔线、chevron、行文字色**这些「通用设置列表语言」是可 1:1 的部分。

### 1.3 投诉反馈：原版右上角有「我的」，我方没有

- 原版 `m3/complaint.xml`：`我的 [1056,115][1213,272]`（157×157）——**在标题栏右侧**，属一级页控件。
- 我方 `buildComplaint()`（`:210-217`）：只有两行 `问题反馈` / `订单投诉`，**没有「我的」节点**（文案 assets 里有 `我的`，但代码没有渲染它）。
- 我方一级页 `订单投诉` 右侧还多了一句 `未选择任何订单`（`:216`），原版一级页 dump **没有这句**（该句只出现在二级表单页 `complaint-form.xml` 的 `[804,341][1111,420]`）。

## 4. 第 1 条：`CompassView` 现在到底画了什么

文件 `app/android/app/src/main/java/com/luopan/fengshui/CompassView.java`（549 行，`git diff origin/develop` 为空，即与 develop 一致）。

### 4.2 红色十字经线的实际代码（`:423-428`）

```java
// Fixed crosshair + top pointer (screen space).
paint.setColor(Color.argb(120, 180, 50, 50));
paint.setStrokeWidth(1f);
canvas.drawLine(cx, cy - r, cx, cy + r, paint);
paint.setColor(Color.argb(80, 180, 50, 50));
canvas.drawLine(cx - r, cy, cx + r, cy, paint);
```

- **颜色**：竖 `argb(120,180,50,50)`（α=47%）、横 `argb(80,180,50,50)`（α=31%），基色 `(180,50,50)` 暗红
- **线宽**：`1f` 像素（**未乘 density**，在 3.375 上等于 0.30dp）
- **长度**：`cy±r` / `cx±r`，`r = min(cx,cy) - 8` → 屏宽 1228 时 r≈606，**跨度 1212px**
- **不随 heading 转**：`cx/cy/r` 都是屏幕坐标，绘制时不套 `heading`
- **顶部红三角**（`:429-436`）：`Color.rgb(200,40,40)` 实心，底半宽 10px、高 16px，受 `showPointer` 控制（K-01「指针开关」）

### 4.3 与原版量化对照

原版出处：`docs/evidence/original-apk/measurements.md:14`（「十字线/指针」条）+ `:9`；`docs/evidence/original-apk/README.md:58`。

| 项 | 原版 | 我方 | 量化差 |
|---|---|---|---|
| 色值 | 纯红 `[255,0,0]`，不透明 | 基色 `(180,50,50)`，α 47%/31% | 红通道 −75；叠在地形上合成后 ≈ 无对比度 |
| 线宽 | **5–6 px**（列 611–616 / 行 1347–1353） | **1 px** | −4~5 px |
| 长度 | **贯穿全屏**（竖线横跨 2578、横线横跨 1228） | 圆直径 1212px | 上下各少 ≈683px |
| 横竖是否同规格 | 同一条纯红，无 α 区分 | 竖 α120 / 横 α80 | 不一致 |
| 是否随朝向转 | 否（固定 `x=614`、`y=1350`） | 否 | **一致** |
| 中心轴盘 | 灰色轴盘 `d≈46px` | 无（仅 `trustEnabled` 时金圈 `r*0.085≈52px`） | 缺 |
| 指针 | 红/蓝**双三角沿水平轴**（红右/蓝左），总长 ≈285px；「上半段就是 0° 指北轴，截图中没有额外的实心三角箭头」 | 顶部**单个**红三角 20×16px | 我方多一个原版没有的顶部箭头 |

**结论（只做定性，不改码）**：第 1 条不是「没画十字」，而是**画了但不可见**——α 47%/31% + 1px + 只覆盖圆径。修的方向是「色值/线宽/跨度/去掉顶部三角」四条，属 `onDraw` 内小改，不涉及渲染通道。

### 4.4 一处必须先统一的取证冲突（第 1 条与第 3 条共同前置）

- `measurements.md:14`：原版指针是**水平轴红/蓝双三角**，无额外箭头
- `docs/fidelity/verify-round2.md:56`：原版 `pointer` 节点 `[573,1188][654,1512]`（81×324，**竖向**）

两处都在说「指针」，但一个是像素测量、一个是 a11y 节点树。**在我方改指针/三角之前，需要逆向给一条口径**：`pointer` 节点是不是就是那根竖红线（324 高覆盖中心区），双三角是否另属 canvas 绘制。这条不定性，第 3 条「符号怪异」会改错。
