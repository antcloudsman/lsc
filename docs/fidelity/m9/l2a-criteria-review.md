## A 组：不补则判据不成立

### A1 分母必须锁「掩膜像素数」
盘面在 1456 画布上直径占 37.5%（`map.html:3004` 注释「盘面只占画布的 37.5%，居中」），盘径 ≈549 → 掩膜 ≈ 23.7 万 px；全画布 1456² = 212 万 px，**差 8.96 倍**。
若分母写成全画布，2% = 42,399 px ≈ 盘面面积的 18%，判据失去判别力。
⇒ 判据须写「分母 = 掩膜像素数」，报告同时给**比例与绝对像素数**两列。

### A2 掩膜只能由 canvas 的 alpha 通道生成
`drawCompass()` 每帧先 `ctx.clearRect(0, 0, size, size)`（`map.html:2807`），canvas 盘外真透明，`alpha>250` 可用；而原生 screencap **整图不透明**，若用它算 `alpha>250`，掩膜退化为全屏，A1 的分母随之失效。
⇒ 判据须写「掩膜由 canvas 侧生成，同一掩膜套两张图」。

### A3 环存在性必须双向
现判据只判「native 有、canvas 无（连续段 ≥3°）」。A 轮（M9-A）的教训是**多画与少画都会发生**（顶部红三角即多画）。
⇒ 须改为 `native-only ≥3°` 与 `canvas-only ≥3°` 双向，任一成立即 FAIL，报告中分别列段。

### A4 时序锚点用 `groundRenderSeq`，`sig` 只能当类型锚
`sig` 只随 `dialType` 变，同类型下的重绘（透明度重算、纹理重建、脏标记复位）**不改 sig**，守卫会放行旧图。
⇒ 取图前后 `groundRenderSeq` 必须相等且 `texDirty===false`；`sig` 保留作「类型一致」校验。地图侧已确认新增 `groundRenderSeq`（每次贴地画布重绘成功自增）。

## B 组：建议同时补（不补我仍可签，但报告要说明为什么没补）

### B1 阈值用「同实现基线」定，不直接写 2%
测试实测：1456 空间 + σ=1.5 的**地板差异 = 3.33%**，固定 2% 会把正确实现判 FAIL。
⇒ 判据改为 `占比 ≤ B + 1.0pp`，`B` = 同实现控制组（两侧同路径出图）的实测基线，且 `B` 与最终阈值都写进报告。

### B2 逐环半径数值对照（`Δr ≤ 1.5px`，归一化到 1456）
存在性向量只判「有没有」，半径才判「位置对不对」。两项并列后，结构层才闭环。

## 一条技术判断（供总监裁「原生单帧导出」）

若原生侧走 screencap（1228×2700）裁+缩到 1456，则 3.33% 是**这条通道的地板**（插值进来的），不是盘面真实差；且 screencap 是屏幕合成后的图，会把背景与亮度混进差异。
若改为「原生把 `CompassView` 直接 draw 到 1456 Bitmap」（地图提的 debug 命令，`evaluateJavascript` 回调落盘，不受 logcat 行长限制），则两侧都是 1456 原生出图，**插值这一环消失**，地板应降到只剩抗锯齿/半像素，2% 类阈值才有意义；同时掩膜两侧各自可算、可交叉核对。
⇒ 我方判断：**该加**，理由是判据性（消掉三个混淆源），不是省事。

## 7. 判据定稿：六层，缺一层漏一类（每层都有实测支撑）

| # | 判据 | 抓什么 | 实测支撑（LC测试自检） |
|---|---|---|---|
| ① 比例 | 掩膜内差异像素占比 + 绝对像素 + maxChannelDiff；分母=掩膜（本机 1456²/掩膜 ≈ 43.76×） | 多画 / 错色 | 多画 20° 弧 → **2.59%** 红 |
| ② 平移搜索（整数 ±1） | 错位 | 1px 错位比例只有 **0.35%**，① 无感，只有它能抓 |
| ③ 逐环双向存在性（native-only 与 canvas-only，≥3°） | 缺失 / 多余 | 缺 350° 环比例只有 **0.20%**（落在掩膜外），只有它能抓 |
| ④ 时序锚 `groundRenderSeq`（+`texDirty` 仅记录）+ **双侧 `faceKind`** | 旧图 / 矢量降级盘冒充位图 | `renderSeq` 在矢量降级时也会自增（`map.html:3132` `dialImg` 为 null 即走 vectorFace，`:3142` 仍自增） |
| ⑤ 阈值 = **噪声地板 `B_noise`** + margin（先签字后取数） | 阈值拍脑袋 / 自己和自己比 | 通道地板 3.33%（screencap→1456），固定 2% 会把正确实现判 FAIL |
| ⑥ 逐环半径 `Δr ≤ 1.5px` | 环整体缩放/偏移 | 环外扩 3px → **Δr=3.0px** ×4 条 FAIL |

### 7.5 `B` 的定义（按产品治理意见收窄，防止自证）
```
B_noise = 同侧、同管线、同一状态重跑 N≥2 次的最大差异（占比 + maxChannelDiff）
用途     = 只决定 margin 的下限（阈值 ≥ B_noise）
禁止     = 用 B_noise 当“像不像”的参照；参照物永远是 native
```
若把 B 取成「canvas 自己两次重跑」，则 canvas 画错时 B 跟着变、阈值随之漂移，判据会恒绿——这正是本轮已出现多次的「规则指向不存在的对象」错误模式。

### 7.6 `faceKind` 必须双侧同名同语义（画时记录，不是读时推断）
```
faceKind : "bitmap" | "vector"    两侧都记
dialTypeUsed : 实际绘制所用类型
守卫：两侧 faceKind=="bitmap" 且 dialTypeUsed==期望；否则继续等，超时按第 8 节原因码记
```
理由：canvas 侧 `dialImg` 为 null 时走矢量盘且 `renderSeq` 照样自增；原生侧 `artwork==null` 时走线稿。不记 `faceKind`，L2a 会把「矢量盘 vs 位图盘」当成盘面差异。

## 8. 结果签署清单（缺任一项不签）

1. **参照物四项**必须同时成立并写入报告：`native`（非 screencap、非 B 基线）、`alpha=1.0` 同档、`1456` 同尺寸、`faceKind=bitmap`；
2. 六层判据逐层读数：`PARAMS / MASK / PIXELS / BLOCKS / SHIFT / RING / RADIUS` 全部打印；
3. 三个负向对照实测读数：错位 1px、缺一条环、多一条环（建议再加环外扩 3px）；
4. `B_noise` 实测值、margin 取法、最终阈值，且**阈值须早于取数签字**；
5. `SKIP` 必须带原因码，三类分开记，不许合并成「未验」：
   - `SKIP-A` 接口未实现（`export-dial` 未落地）→ 本项未验，等接口；
   - `SKIP-B` `faceKind` 超时仍为 `vector` → **可能的真缺陷**（用户看到的是矢量降级盘），单列一条「位图降级」并复测；
   - `SKIP-C` `seq`/内容条件不收敛 → 取样无效，可重跑。
6. **只读口 `dialPx` 当前失效，不得直接引用**（已知缺陷 `M9-D1`，M10 修）：
   - `groundCanvasMeta().dialPx` 输出的是**画布边长 1456**，不是盘面直径 549（`dcab5c0:3077` `dialPx: sz.px`）；`off` 输出 **453.422**（用未取整的 `sz.px×0.37725` 算），而渲染器用的是 **453.5**（`(1456−549)/2`）。
   - 取数时自算，两种写法等价，任选其一并写进报告：
     ```
     dial = round(w × 0.37725) = 549        （或 round(meta.dialPx − 2×meta.off) = round(549.156) = 549）
     off  = (w − dial) / 2     = 453.5      ← 几何判据必须用这个，不用 453.422
     ```
   - 报告中引用该字段时须注明「字段当前失效」，**不得把 1456 当盘面直径**、也不得用 453.422 反推盘心（会得 727.92，仍在 728±1 内但白丢精度）。
