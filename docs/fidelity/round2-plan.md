## 8. 「至少 1:1」判定方式（三条同时满足才算达标）

1. **逐项差异关闭**：P0 7 + P1 13 + P2 5 = **25 条**全部状态改「已关闭」，每条附：代码提交号 + 同状态 orig/lc 双图 + dump + 量化值达标（按 §2–§4 判据）+ 复验人签字。DI 4、NC 3、待补采 2、未确认 1、缺失 1、等价 1 按登记口径收口（不要求修复，但必须有决策编号/证据/原因），**不允许「未核」或「待补」混杂在关闭项里**。
2. **独立抽样复验**：由非实现人复验 **≥20%（≥8/37）**，覆盖 P0 ≥3、P1 ≥3、P2 ≥1、DI/NC ≥1；**误判 0**（复验发现一条判定错误即整体不达标，修完重抽）。
3. **配对门禁通过**：`fidelity.py report` 运行通过，且：`duplicates=0`（allow 列表除外）、`zero_byte=0`、`missing_orig=0`、`lc_only=4` 合规；`missing_lc=0`，或**仅限三类**逐条豁免（每条带 reason/by）：① 原版独有态转 DI；② 命名对齐——**必须先尝试对齐（stem / `checksheet_id`），确配不上才可豁免**；③ 证据不可得且已登记（FLAG_SECURE / 设备限制）。**禁止成片豁免**；索引 100% 有 `checksheet_id` 与双图/dump 落点。

> 不达标处理：任一条件不满足 → **不得对外报「1:1 达标」**；缺口退回对应里程碑，计划与报告同步改状态。
