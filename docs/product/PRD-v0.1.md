## 1. 自用增量的判据与开关规矩

### 1.1 判据（替代市场判据）

一个功能进池子的三问，**三问都过才做**：

1. **会用几次**：日常「看山水 / 定坐向」时，一周内会不会自然用到？（估不出频次的直接进 P2）
2. **不用会不会错**：不做的话，会不会导致读数怀疑、白跑一趟、图存不下来？
3. **代价**：粗估人日是否超过它省下的时间？（自用项目没有用户增长兜底，成本必须划算）

不满足的典型：换肤、AR 实景、多端同步、历史影像对比、多语言——**明确不做**，见 §3 末尾「不做清单」。

### 1.2 开关规矩（不变，且先解决「开关放哪」）

1. **增量必须可开关、默认全关**；关闭时基线不出现任何新按钮/入口/权限请求。
2. **基线验收在全关状态跑**（craft 三关、真机冒烟、截图对照）；开关打开只做专项验收。
3. **不碰 mechanics.json 的 19 项**，不改 `CompassData.read()` 既有输出；新读数（海拔/坡度）走独立通道。
4. **一功能一开关**，不做总开关。
5. **落点问题**：当前 App 没有设置页（B-21，原版是否存在未确认）。所以先做 **P0-0 隐藏入口 + 实验开关页**：连续点「知识库」页签标题 7 次进入，页内只有开关列表；不做齿轮图标，避免改基线布局。

## 3. 增量功能池（自用价值排序）

> 工作量 = 粗估人日（±50%，含自测，不含真机排队）；`影响 1:1`：不触碰＝纯新增且可关；触碰＝改布局/读数链路，必须开关隔离。
> 判据标签：`省一步`＝少一次操作；`省怀疑`＝少一次「读数对不对」；`省跑一趟`＝出门前/现场少返工。

### P0（M2 必须做）

#### P0-0 实验开关页（隐藏入口）

- 用户故事：作为自己，我要能一键关掉任何实验功能，回到和原版一致的基线，不给自己制造「这是不是增量搞的」疑问。
- 做法：连续点「知识库」页签标题 7 次 → 打开开关列表（每行：功能名 + 开关 + 一行说明）；无齿轮图标、无新权限。
- 验收标准：
  1. 全关状态下，基线截图与当前版本逐像素一致（除时间/电量等系统元素）。
  2. 开关状态落盘，杀进程重开保持。
  3. 关闭某功能后，其入口/状态条/弹窗全部消失，不残留。
- 粗估：**1–2 人日**｜影响 1:1：不触碰（隐藏入口）｜依赖：无
- 依据：内部（章程要求可开关，但当前无落点）

#### P0-1 读数可信包：校准 + 磁偏角 + 精度/倾斜提示 + 天池

- 用户故事：作为自己，读数偏了我要知道为什么、怎么校；不想像开运那样「偏差 75 度」还不知道哪里错了。
- 现状：`MainActivity.onSensorChanged()` 直接取 `SensorManager.getOrientation` 的 azimuth，无磁偏角、无精度反馈；`onAccuracyChanged()` 是空实现。
- 功能点：
  1. 方位角与传感器精度（高/中/低）状态条；低精度时黄字提示。
  2. 手持倾斜提示：由 `orientation[1]/[2]` 算俯仰/横滚，>5° 时提示「请端平」，不阻塞使用。
  3. 「8 字校准」引导（一次性，可跳过）。
  4. 磁偏角：手动 −30°…+30°（0.1° 步进）；状态条标明当前按「磁北 / 真北」哪种口径。
  5. 罗盘中心天池指针 + 天心十道十字线（视觉，参考开运/iOS 差评）。
- 验收标准：
  1. 手动设 +5.0° 后，「度数」与全部环文字同步偏转 5.0°（±0.1°）；坐向/三盘/分金/龙一致，不出现只改一处。
  2. 真北口径下，真机对照手机自带指南针/在线磁偏角数据，差值 ≤2°（写明测量方法）。
  3. 倾斜 >5° 出现提示、回正后消失；精度低时状态条变黄，恢复后复原。
  4. 全关时：无状态条、无引导、罗盘中心与基线一致。
- 粗估：**4–6 人日**｜影响 1:1：**触碰**（状态条 + 罗盘中心）｜依赖：LC客户端；磁偏角算法口径需 LC逆向/技术总监确认
- 依据：市场（开运「偏差 75 度」、iOS 坐向差评）+ 自用判据「省怀疑」

#### P0-2 一键留档：截图 + 读数合成 + 本地记录

- 用户故事：作为自己，现场定完坐向想留一张「时间 + 地点 + 读数 + 山景」的图，而不是手抄。
- 现状：`captureMap()` 截错对象（见 B-09），且不含罗盘与读数；无记录能力。
- 功能点：
  1. 修截图：截当前 Tab 的内容（罗盘 Tab = 底图 + 罗盘 + 读数条；地图 Tab = 地图/3D 画布）。
  2. 合成一张卡片：地图/3D 画面 + 读数（度数/坐向/分金/72 龙/60 龙）+ 时间 + 坐标（未授权则「未授权」）。
  3. 本地记录列表：时间倒序，可改名、可删、可单条重看；存的是**当时的读数快照**，不重算。
  4. 分享：系统分享单张图。
- 验收标准：
  1. 罗盘 Tab 点「截图」得到 ≥1080px 宽的 PNG，含罗盘 + 读数 + 时间，无黑边/空白。
  2. 3D 模式截图取 WebGL 画布（`preserveDrawingBuffer` 已开），山体正常、非黑屏。
  3. 存 3 条记录，杀进程重开仍在；回看读数与保存时逐字一致。
  4. 无定位权限也能存，坐标显示「未授权」，不崩溃。
  5. 全关：罗盘页无「存记录」入口。
- 粗估：**6–8 人日**｜影响 1:1：不触碰（新增入口）｜依赖：先修 B-09/B-27（LC客户端）
- 依据：市场（7 款竞品简介均未明示「测量记录」，属自用刚需）+ 自用判据「省一步」

#### P0-3 离线与弱网降级

- 用户故事：作为自己，山里没信号也要能看罗盘、看知识库，以及刚才看过的那片山，而不是空白。
- 现状：`map.html.fillLayer()` 每次重建 `<img>`，瓦片 `onerror` 直接 `display:none` → 断网变纯色；3D 的 DEM 来自 `s3.amazonaws.com`（境外源），失败只显示「DEM 加载失败」。
- 功能点：
  1. 罗盘 / 读数 / 知识库 / 记录完全离线可用（验收即可）。
  2. 2D 瓦片本地缓存（LRU 上限 + 「清空缓存」按钮）。
  3. 断网/瓦片失败：地图区显示「网络不可用 / 已显示缓存」，不反复重试。
  4. DEM 源失败：提示并回落 2D（已有 `setHud + setMode('2d')` 雏形），不白屏。
- 验收标准：
  1. 飞行模式冷启动：罗盘可转、读数正常、知识库可开、记录可看；地图区有明确离线提示。
  2. 在线看 A 区域 → 断网 → 重开 → A 区域仍有瓦片；清缓存后必须联网才能看（可复现）。
  3. DEM 源不可达时 5s 内回落 2D 并提示，不出现无限「加载中」。
- 粗估：**4–6 人日**（LC地图 3–4 + 客户端 1 + 测试 1）｜影响 1:1：不触碰｜依赖：LC地图
- 依据：市场（「打不开」差评）+ 自用判据「省跑一趟」

#### P0-4 3D 点读：海拔 / 坡度 / 坡向 + 垂直夸张透明化 + 3D 立向标记

- 用户故事：作为自己，我要在 3D 上点一下就知道「这里多高、朝哪、陡不陡」，还要知道画面被垂直放大了几倍，别误判山势。
- 现状：3D 引擎已用 Terrarium DEM 真高程渲染（`buildMesh()`、`VEXAG=2.5` 垂直放大写死），但：
  - `placeMarker()` 在 3D 直接 `return`，**点选未实现**（代码注释自认「需射线拾取，本轮未实现」）；
  - HUD 只显示中心点海拔，无坡度/坡向；
  - 垂直夸张 2.5 倍**界面上没写**，容易把陡坡看成绝壁。
- 功能点：
  1. 3D 点选（射线拾取）：显示该点经纬度、海拔、坡度（°）、坡向（八向 + 度数）。
  2. 点选后在山上打「立向」标记，复用 2D 的标记语义与清除。
  3. HUD 增加「垂直放大 2.5×」标识；设置里可改 1.0×/2.5×/4.0×（默认 2.5×）。
  4. 点选读数只做客观量，不做任何吉凶判断。
- 验收标准：
  1. 点选高程与 HUD 中心海拔同源（同一格点误差为 0）；坡度/坡向用 3×3 邻域差分，与手算一致（写进测试）。
  2. 连续点 10 个点，读数不串位（每次点击更新当前点标记 + 数值）。
  3. 俯仰 0° 与 60° 下点选都命中正确位置（误差 ≤1 个网格）。
  4. 切换垂直放大后，同一位置海拔读数不变、地形起伏变化可见。
  5. 全关：回到当前 3D 行为（无点选、无倍率标识）。
- 粗估：**4–6 人日**（LC地图 3–4 + 测试 1–2；引擎已有，只补拾取与读数）
- 影响 1:1：**等价替代**（原版 3D 为 VM 保护，不可复刻）｜依赖：LC地图（主）
- 依据：市场（堪舆/山水地图都把「海拔高程、坡度坡向」当卖点）+ 自用判据「省怀疑」

### P1（P0 之后，按自用频次决定）

#### P1-1 地名 / 坐标搜索跳转

- 用户故事：想到某座山、某个村，直接搜过去看，而不是在地图上找半天。
- 验收标准：输入地名或「纬度,经度」可跳转并居中；无结果时明确提示；跳转后 2D/3D 都可看；全关无搜索框。
- 粗估：**3–5 人日**｜影响 1:1：不触碰｜依赖：LC地图（天地图搜索 API，注意配额）｜依据：市场（一起看地图）
- 风险：搜索 API 走天地图 key，调用量翻倍 → 与 P0-3 的缓存/降级一起设计。

#### P1-2 距离 / 面积量测 + 多点标注

- 用户故事：看一块地、两座山之间的距离，点几下出数。
- 验收标准：两点距离误差 ≤1%（对照已知地标）；多边形面积按球面公式；标注可删、可存进记录；全关无入口。
- 粗估：**4–6 人日**｜影响 1:1：不触碰｜依赖：LC地图｜依据：市场（一起看地图「测量分析」）

#### P1-3 地形剖面（两点连线看起伏）

- 用户故事：判断山脊走向、视线遮挡，要一条线上的高程曲线。
- 验收标准：剖面采样与 DEM 一致（可复算）；可拖动查看峰值/谷值海拔；全关无入口。
- 粗估：**3–5 人日**｜影响 1:1：不触碰｜依赖：LC地图（DEM 已就绪）｜依据：自推（无竞品明示，自用高频）

#### P1-4 输入度数 → 坐向速查

- 用户故事：别人报「160 度」，我要立刻知道向什么、坐什么、兼不兼。
- 验收标准：输入 0–359.99 输出与 `CompassData.read()` 完全一致（含正兼向、分金、龙）；与罗盘页同一套表，禁止第二份实现；全关无入口。
- 粗估：**2–3 人日**｜影响 1:1：触碰（复用读数链路，需开关）｜依赖：LC客户端｜依据：市场（iOS 風水羅盤「输入 160 度」的使用方式）

#### P1-5 等高线叠加

- 用户故事：3D 晕渲看不出等高差，叠等高线更直观。
- 验收标准：等高距可选（如 50/100/200m）；线与 DEM 一致（抽检 3 处）；可关。
- 粗估：**5–8 人日**｜影响 1:1：不触碰｜依赖：LC地图｜依据：市场（山水地图「等高线分析」）

### P2（观察，暂不排期）

#### P2-1 街景

- 自用价值：看房子周边、进山路口。依赖天地图街景可用性与配额；实现前先做一次可用性 spike。
- 粗估：**4–6 人日**｜影响 1:1：不触碰（原版缺失项，属补全）｜依据：市场（原版有、一起看地图有）

#### P2-2 老黄历 / 择日（纯本地展示）

- 约束：只展示公开历法数据，不生成吉凶建议；默认关。
- 粗估：**5–8 人日**｜影响 1:1：不触碰｜依据：市场（山水地图）

## 5. 合规注意点（自用，与 market-scan §4 同口径）

1. **天地图个人 key 配额**：个人注册每服务每天 1 万次；key 明文内置在 `map.html`，APK 外传即泄露。自用要换自己 key、瓦片缓存、失败降级。
2. **风水内容仅本地使用**：不发布、不传播含吉凶断语的成品；把地图截图公开/发给他人时才需按地图规定标注来源与审图号。
3. **不接第三方付费/广告 SDK，不上传位置与记录**：保持纯本地，就不涉及「互联网地图服务」资质问题。

## 7. 开放问题（需用户/技术总监拍板）

1. **主力场景**：自用更常是「出门看山势」还是「现场定坐向」？—— 直接决定 P0 排序（我看山势/坐向各半，先按「读数可信 → 3D 点读 → 留档 → 离线」排）。

3. **DEM 源**：3D 现在用境外 `s3.amazonaws.com` 的 Terrarium 高程瓦片；国内网络可能慢。是否改为天地图/其他可达源，或做本地高程缓存？
