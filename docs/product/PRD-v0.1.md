## 1. 自用增量的判据与开关规矩

### 1.1 判据（替代市场判据）

一个功能进池子的三问，**三问都过才做**：

1. **会用几次**：日常「看山水 / 定坐向」时，一周内会不会自然用到？（估不出频次的直接进 P2）
2. **不用会不会错**：不做的话，会不会导致读数怀疑、白跑一趟、图存不下来？
3. **代价**：粗估人日是否超过它省下的时间？（自用项目没有用户增长兜底，成本必须划算）

不满足的典型：换肤、AR 实景、多端同步、历史影像对比、多语言——**明确不做**，见 §3 末尾「不做清单」。

### 1.2 开关规矩（不变，且先解决「开关放哪」）

1. **增量必须可开关、默认全关**；关闭时基线不出现任何新按钮/入口/权限请求。
2. **基线验收在全关状态跑**（craft 三关、真机冒烟、截图对照）；开关打开只做专项验收。
3. **不碰 mechanics.json 的 19 项**，不改 `CompassData.read()` 既有输出；新读数（海拔/坡度）走独立通道。
4. **一功能一开关**，不做总开关。
5. **落点问题**：当前 App 没有设置页（B-21）。原版有没有设置页**与本条无关**（T-3）：自用版本必须有开关入口。所以先做 **P0-0 隐藏入口 + 实验开关页**：连续点「知识库」页签 7 次进入，页内只有开关列表；不做齿轮图标，避免改基线布局。

## 3. 增量功能池（自用价值排序）

> 工作量 = 粗估人日（±50%，含自测，不含真机排队）；`影响 1:1`：不触碰＝纯新增且可关；触碰＝改布局/读数链路，必须开关隔离。
> 判据标签：`省一步`＝少一次操作；`省怀疑`＝少一次「读数对不对」；`省跑一趟`＝出门前/现场少返工。

### P0（M2 必须做）

#### P0-0 实验开关页（隐藏入口）

- 用户故事：作为自己，我要能一键关掉任何实验功能，回到和原版一致的基线，不给自己制造「这是不是增量搞的」疑问。
- 做法：连续点「知识库」页签 **7 次**（每次间隔 <500ms）→ 打开开关列表（页标题「实验功能」，每行：功能名 + 开关 + 一行说明）；无齿轮图标、无新权限。
- 验收标准（**与原版是否有设置页无关**，T-3；可直接执行见 `docs/qa/AT-P0-0-feature-switch.md`——**待 LC测试 建，未落盘前以本条为准**）：
  1. **隐藏性**：连点 6 次不出现；第 7 次出现；面板打开时底部三 Tab 仍可见、返回键可关闭面板。
  2. **全关即基线**：全部开关关闭时，三个 Tab 的截图与改动前基线一致（逐像素，裁剪掉状态栏/时间后 diff = 0）。
  3. **落盘**：开关状态写 `shared_prefs/lc_features.xml`（debug 可 `adb shell run-as ... cat` 校验）；`am force-stop` 后重开，状态与关闭前一致。
  4. **无残留**：关闭某功能后，它的按钮/状态条/弹窗/日志全部消失；再打开能恢复，无需重启。
  5. **一功能一开关**：面板行数 = 已落地增量数，名称带 PRD 编号（如「P0-1 读数可信包」），**没有「全部开启」总开关**。
  6. **不多要权限**：`adb shell dumpsys package com.luopan.fengshui` 的权限列表与基线一致。
  7. 开关页本身不读写罗盘状态：打开面板再返回，罗盘继续跟转、读数不变。
- 粗估：**1–2 人日**｜影响 1:1：不触碰（隐藏入口）｜依赖：无
- 依据：内部（章程要求可开关，但当前无落点）

#### P0-1 读数可信包：校准 + 磁偏角 + 精度/倾斜提示 + 天池

- 用户故事：作为自己，读数偏了我要知道为什么、怎么校；不想像开运那样「偏差 75 度」还不知道哪里错了。
- 现状：`MainActivity.onSensorChanged()` 直接取 `SensorManager.getOrientation` 的 azimuth，无磁偏角、无精度反馈；`onAccuracyChanged()` 是空实现。
- **口径定义（避免测试歧义）**：显示与全部环统一用「校正后航向」`H = normalize(raw + declination)`；
  `declination`（磁偏角）是**一个值**，来源二选一：手动输入（−30°…+30°，0.1° 步进）或「按定位自动」；
  `mode`（磁北/真北）只决定这个值**是否参与计算**：磁北 → 不参与（H = raw），真北 → 参与（H = raw + declination）。
- 功能点：
  1. 状态条：当前口径（磁北/真北）+ 传感器精度（高/中/低）；低精度黄字。
  2. 倾斜提示：由 `orientation[1]/[2]` 算俯仰/横滚，>5° 提示「请端平」，不阻塞使用。
  3. 「8 字校准」引导（首次一次，可跳过、可不再提示）。
  4. 磁偏角设置：手动值 / 按定位自动 / 关闭（关闭即磁北口径）。
  5. 罗盘中心天池指针 + 天心十道十字线（视觉）。
- **测试基建要求**（不满足则用例判 BLOCKED，见 `docs/qa/AT-P0-1-reading-trust.md`——**待 LC测试 建，未落盘前以本条为准**）：
  a. 纯静态类 `com.luopan.fengshui.SensorMath`（不 import android.*）：`applyDeclination`、`tiltDegrees`、`isFlat`，供 JVM 对拍；
  b. debug 构建提供广播注入：`com.luopan.fengshui.DEBUG`（`heading` / `accuracy` / `reset`）；
  c. `readingView` 有 id `reading_text`，状态条 id `sensor_status`。
- 验收标准：
  1. **全环同步**：注入 raw=94.0°、磁偏角 +5.0°、真北口径 → 度数显示 99.00°±0.05，且地盘/人盘/天盘/分金/72 龙/60 龙/后天卦 与 `CompassData.read(99.0)` 完全一致（JVM 探针对拍），不出现只改一处。
  2. **口径切换**：切回磁北 → 显示 94.00°、环文字回到 `read(94.0)`；来回切 10 次无累积漂移。
  3. **边界**：raw=357.0 + decl=+5.0 → 显示 2.00°（回绕正确）；−30/+30 极值不溢出、不崩。
  4. **精度提示**：注入 accuracy=1 → 黄字提示；=3 → 提示消失。
  5. **倾斜**：`tiltDegrees` 在 JVM 上对 (pitch,roll) 采样误差 ≤0.1°；真机倾斜 >5° 出现提示、回正消失（人工，截图取证）。
  6. **8 字校准**：`pm clear` 后首次进罗盘出现一次；跳过后再进不再出现。
  7. **全关**：无状态条、无引导、罗盘中心与基线一致，`reading_text` 与基线逐字相同。
  8. **不掩盖既有缺陷**：人盘/天盘仍取 `mechanics.json` 的表与偏移，**不得**为了「三盘不同」而硬编码新偏移（该缺陷修复以逆向取证为准，T-5）。

#### P0-2 一键留档：截图 + 读数合成 + 本地记录

- 用户故事：作为自己，现场定完坐向想留一张「时间 + 地点 + 读数 + 山景」的图，而不是手抄。

  4. 无定位权限也能存，坐标显示「未授权」，不崩溃。

#### P0-3 离线与弱网降级

- 用户故事：作为自己，山里没信号也要能看罗盘、看知识库，以及刚才看过的那片山，而不是空白。
- 现状：`map.html.fillLayer()` 每次重建 `<img>`，瓦片 `onerror` 直接 `display:none` → 断网变纯色；3D 的 DEM 来自 `s3.amazonaws.com`（境外源），失败只显示「DEM 加载失败」。
- 功能点：
  1. 罗盘 / 读数 / 知识库 / 记录完全离线可用（验收即可）。

  3. 断网/瓦片失败：地图区显示「网络不可用 / 已显示缓存」，不反复重试。

  1. 飞行模式冷启动：罗盘可转、读数正常、知识库可开、记录可看；地图区有明确离线提示。

#### P0-4 3D 点读：海拔 / 坡度 / 坡向 + 垂直夸张透明化 + 3D 立向标记

- **已拍板：3D 走路径 A**（T-2）——客户端直连官方/公开 DEM（Terrarium 高程瓦片）在线渲染 + 天地图底图贴图；**允许本地磁盘缓存加速，但不自建 DEM 瓦片服务、不对外提供瓦片**。本项只做「读数与交互」，不动数据链路。
- 用户故事：作为自己，我要在 3D 上点一下就知道「这里多高、朝哪、陡不陡」，还要知道画面被垂直放大了几倍，别误判山势。
- 现状：3D 引擎已用 Terrarium DEM 真高程渲染（`buildMesh()`、`VEXAG=2.5` 垂直放大写死），但：
  - `placeMarker()` 在 3D 直接 `return`，**点选未实现**（代码注释自认「需射线拾取，本轮未实现」）；
  - HUD 只显示中心点海拔，无坡度/坡向；
  - 垂直夸张 2.5 倍**界面上没写**，容易把陡坡看成绝壁。
- 功能点：
  1. 3D 点选（射线拾取）：显示该点经纬度、**真实海拔**（未乘垂直放大）、坡度（°）、坡向（八向 + 度数）。
  2. 点选后在山上打「立向」标记，复用 2D 的标记语义与清除。
  3. HUD 增加「垂直放大 2.5×」标识；开关页里可改 1.0×/2.5×/4.0×（默认 2.5×）。
  4. 点选读数只做客观量，不做任何吉凶判断。
  5. DEM 瓦片缺块时必须报「无数据」，**不得**把缺块当 0 m（现 `demAt()` 缺块返回 0，会造出「假海平面」）。
- **测试基建要求**（不满足则用例判 BLOCKED，见 `docs/qa/AT-P0-4-3d-probe.md`）：
  a. `window.__LC3D` 增：`probe(lat,lng)` → `{elev,slope,aspect}`（纯 DEM 采样、不依赖渲染）、`pick(px,py)` → 同结构 + `{lat,lng}`、`state()` 增 `vexag`；
  b. `onConsoleMessage` 转发到 logcat tag `LCJS`（结构化行：`LCPICK ...`、`LCVEXAG ...`、`LC3D marker n=..`）。
- 验收标准：
  1. **数值**：`probe()` 海拔与独立计算（同一 DEM 瓦片、同一双线性插值）误差 ≤1 m；坡度 ≤0.5°、坡向 ≤2°（测试脚本见 AT 文档）。
  2. **命中**：默认视角（中心 39.9042/116.4074，3D 强制 z9）下点画布中心 → 返回经纬度与中心差 ≤1 个网格步长；俯仰 0° 与 60° 各测一次都成立。
  3. **倍率透明**：HUD 文案与 `state().vexag` 一致；切到 1.0× 后同一位置**海拔读数不变**、起伏变化可见。
  4. **连续点选**：连点 10 次，每次日志独立且标记数正确递增；「清除标记」后 `LC3D marker n=0`。
  5. **缺块**：断网或把 DEM 请求打到不存在的瓦片，`probe()` 返回「无数据」而不是 0 m。
  6. **性能**：默认视角 `fps ≥30`（连续 10s），操作 5 分钟无 FATAL。
  7. **全关**：点选无响应、无倍率标识、无标记；3D 基本渲染与当前一致。
  8. **不碰基线**：`tests/numeric` 全绿，`mechanics.json` 19 项 0 改动；2D 读数与开关关闭时逐字一致。
- 粗估：**4–6 人日**（LC地图 3–4 + 测试 1–2；引擎已有，只补拾取与读数）
- 影响 1:1：**等价替代**（原版 3D 为 VM 保护，不可复刻）｜依赖：LC地图（主）
- 依据：市场（堪舆/山水地图都把「海拔高程、坡度坡向」当卖点）+ 自用判据「省怀疑」

## 5. 合规注意点（自用，与 market-scan §4 同口径）

1. **天地图个人 key 配额**：个人注册每服务每天 1 万次；key 明文内置在 `map.html`，APK 外传即泄露。自用要换自己 key、瓦片缓存、失败降级；**不自建瓦片服务、不对外提供瓦片**（T-2）。
2. **风水内容仅本地使用**：不发布、不传播含吉凶断语的成品；把地图截图公开/发给他人时才需按地图规定标注来源与审图号。
3. **不接第三方付费/广告 SDK，不上传位置与记录**：保持纯本地，就不涉及「互联网地图服务」资质问题；3D 高程与底图只做在线渲染 + 本地缓存（自建 DEM 瓦片服务即落入测绘资质与「派生产品」条款，明确不做）。
