## 3. 建议（**全部是建议，不是结论**）

> 排序依据：先补「地形侧缺的标配」（C3 覆盖最广），再补「头部产品的卖点」（C1/C2），最后做锦上添花（C6）。
> 人日 = 480 分钟；估算法在每条末尾写明。

### 建议 1｜补齐地形侧「标配五项」中的 KML 导入导出（P0）
- **建议内容**：点位/轨迹导出 KML（Google Earth 可读）+ 导入 KML 显示为图层。本项目现有点位体系与轨迹已在库，导出属薄封装。
- **依据**：C3 —— BIGEMAP、GPS工具箱 明确命中 KML；Tooboo 亦命中。
- **工作量估算：3.0 人日**。依据：KML/KMZ 序列化 + 文件选择（SAF）+ 坐标系与字段映射 1.5 人日；导入解析与图层渲染 1.0 人日；真机双向验证与异常路径 0.5 人日。

### 建议 2｜离线降级：瓦片缓存 + 离线态明示（P0）
- **建议内容**：按可视范围/按图层预缓，离线时明确提示「当前为缓存影像，范围已标出」，不静默空白。
- **依据**：C3/C6 —— PeakVisor、Tooboo、BIGEMAP、GPS工具箱 命中「离线」；这是户外场景的硬需求。
- **工作量估算：8.0 人日**。依据：本项目 3D 贴面链路（DEM+贴面+失败态）实际约 5 人日量级，瓦片缓存涉及容量管理、过期策略、离线态 UI 三块，按其 1.6 倍估；含真机断网/弱网验证。

### 建议 3｜盘面库扩展：三元 / 三合 / 金锁玉关 / 玄空飞星（P1）
- **建议内容**：在现有「内置盘面(5)」基础上按派系补 4 套，标注派系名与圈层含义。
- **依据**：C2 —— 巨峰罗盘把「上百种专业罗盘」列为首要卖点，且明确点名这四类。
- **工作量估算：6.0 人日**（1.5 人日/套）。依据：每套 = 圈层矢量绘制 + 圈层数据与角度映射 + 与现有盘面引擎接入 + 单机校验（截图比对刻线）。

### 建议 4｜轻量「黄历 / 宜忌」内容页（P1，需先查数据来源与版权）
- **建议内容**：只做「当日干支 / 宜忌 / 节气」，不做八字排盘（后者是另一条产品线）。
- **依据**：C1 —— 头部产品的评分样本来自命理内容生态，而不是工具本身。
- **工作量估算：3.0 人日**（含数据源接入 1.5、页面 1.0、校验 0.5）。**前置条件**：数据源授权与准确性核验未完成前**不开工**；查不到合法来源则转「未查证」挂起。

### 建议 5｜现场取证：截图带罗盘读数的水印（P2）
- **建议内容**：截图自动叠加「坐向 + 坐标 + 时间 + 海拔」水印，可关闭。
- **依据**：C3 —— BIGEMAP 明确「现场勘验取证（水印相机）」。
- **工作量估算：1.5 人日**（水印布局 + 字体 + 真机验证）。

### 建议 6｜轨迹回放增强：速度/高程曲线（P2）
- **建议内容**：轨迹详情页增加速度与高程曲线，回放时同步游标。
- **依据**：C6 —— 户外侧产品普遍把轨迹做成核心资产。
- **工作量估算：2.0 人日**（曲线渲染 + 数据采样 + 联调）。

**合计建议工作量：23.5 人日**（建议 1+2 为 P0 共 **11.0 人日**，建议 4 若数据源不通则扣 3.0）。

## 5. 风险与合规提示

1. **地图数据与审图号**：竞品多用商业图源（奥维/BIGEMAP 等）；本项目用自建/天地图数据源，**审图号仍为「待核对」**，对外发布前必须闭环（`help-center.md` §13 已按此记）。
2. **天地图 APIKEY 商用配额**：本项目当前为自用；**若转为对外提供，需重新核配额与授权**（此前已定 key 不入库、构建期注入）。
3. **风水内容审核红线**：封建迷信类内容在各 Android 市场审核口径不一；本项目现有定位是「传统测量工具 + 地形读数」，**对外文案应避免疗效/改运类表述**（例如 `巨峰罗盘` 描述里的「挡煞开运」一类说法不要学）。
4. **KML 导出合规**：若未来支持坐标/边界导出，需确认不含涉密地理信息（对外发布前单独评审）。
