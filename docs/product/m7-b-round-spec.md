## 2. KML 支持范围（最小集）

### 2.1 导入（只认这些，其余明确跳过）

| 元素 | 处理 |
|---|---|
| `<Placemark>` + `<Point>` | **支持**（1 个坐标） |
| `<Placemark>` + `<LineString>` | **支持**（≥2 坐标） |
| `<Placemark>` + `<Polygon>` / `<outerBoundaryIs>` | **支持**（取外环；**内环忽略**并计数提示） |
| `<MultiGeometry>` / 多个 Placemark | 逐个 Placemark 读；`MultiGeometry` **跳过**并计入 `skipped` |
| `<Style>` / `<NetworkLink>` / `<GroundOverlay>` / `<gx:Track>` / `<TimeSpan>` | **一律跳过**，计入 `skipped`，导入结束给出「忽略 N 项」提示 |
| 坐标顺序 | KML 为 **经度,纬度[,高程]**（lon,lat），**不要按 lat,lng 读** |

### 2.2 导出（字段固定，便于往返比对）

| 字段 | 位置 | 说明 |
|---|---|---|
| 名称 | `<name>` | 收藏点/轨迹名 |
| 说明 | `<description>` | 纯文本，不含 HTML |
| 坐标系 | `<ExtendedData><Data name="lc:crs">` | **必写**；取值 `WGS84` / `GCJ02` / `CGCS2000` |
| 业务字段 | **逐点** `<ExtendedData>`（写在 `<Placemark>` 内）：`lc:id`、`lc:type`(point/track/area)、`lc:sit`、`lc:heading`、`lc:elev`、`lc:created` | **缺失值一律不写该键**（数值、文本同一规则），导入端按「键不存在 = 未知」处理；**不许写 `0`、不许写空串** |
| 坐标 | `<coordinates>` | **固定 8 位小数**（`%.8f`）；**有海拔**写 `lon,lat,alt`，**无海拔只写 `lon,lat`（省略 alt，禁止补 `,0`）**；点间以空格分隔 |

**导出对象**：① 收藏点（Point）；② 轨迹（LineString，若已存在）；③ 测量结果（Polygon，可选，若无则不做）。
**不做**：样式、图标、照片、时间动画、`gx:` 扩展。

### 2.3 实现对照与缺口（2026-11-08 按 `a46869b` 实读 `KmlIo.java` 核）

**已实现（与口径一致）**：导出统一 WGS84 + **Document 级** `<ExtendedData>` 7 项（`lc:crs` / `lc:coordinate_order` / `lc:generator` / `lc:app` / `lc:exported` / `lc:count` / `lc:source`）；坐标 8 位小数、顺序 `lon,lat,alt`；导入认 Point/LineString/Polygon(外环)，其余跳过计数；无声明提示「坐标系未知，按 WGS84 处理」。

**缺口 B-1（P1，如实记，不在本轮 done-when 内）**：`<Placemark>` 里目前**只有** `<name>`、可选 `<description>`、`<Point><coordinates>lng,lat,0</coordinates>`——**逐点业务字段未导出**：
- 缺 `lc:id` / `lc:type` / `lc:sit`（坐向）/ `lc:heading` / `lc:elev`（海拔）/ `lc:created`；
- 且 `<alt>` **写死 `0`**，与本文件 §2.2「**缺失值一律省略该键**，不写 `0` 冒充」冲突。

**后果（用户视角）**：导出再导入后，点位只剩「名称 + 坐标」，**坐向/海拔/类型/时间全部丢失**；风水场景里「导出给同行看坐向」是核心信息，这条不能长期缺。
**补法（工作量 0.5 人日，总监定为本轮补）**：`<Placemark>` 内加 `<ExtendedData>` 写上述 6 项，**缺失值一律省略该键**（不写 `0`、不写空串，与 M-06 的 `elev=0` 同一规则）；`<coordinates>` 无海拔时**只写 `lon,lat`**；导入端按「键不存在 = 未知」读取；真机复核「导出→清空→导入→坐向/海拔逐点对得上」。
**B-1 复验判据（2026-11-08 按实现事实校正，**不许拿不可能出现的东西判失败**）**：
- **逐点必须是五项**：`lc:id` / `lc:type` / `lc:sit` / `lc:heading` / `lc:created`；
- **`lc:elev` 按值有无**：收藏点表**没有海拔列**，`elevM` 恒为 NaN ⇒ **导出端整个键省略，永远不会出现**。所以判据是「**`lc:sit` 命中数 = 点数**」与「**`lc:elev` 命中数 ≤ 点数**」，**不是**「六项逐点都存在」——写成后者会判一个不可能出现的东西失败；
- **`lc:created` 的边界**：**导出无损、导入不入库**（`GapDb.insertInterest` 写入时取当前时间，不接受调用方指定）⇒ 导入后创建时间变成导入时刻，属**已知限制**（§7），要真正保留需改 M4 收藏表插入签名，不在本轮范围。
**判据① 的比法随之变更（总监 2026-11-08 定，必须写进文档，否则旧脚本会把「省略 alt」误判成「坐标少了」）**：
- **改前**：`coordinates = "113.26438500,23.12911200,0"`（3 值，alt 写死 0）⇒ 按 18 值逐一对；
- **改后**：无海拔 → `"113.26438500,23.12911200"`（2 值）；有海拔 → `"…,…,-1.5"`；
- **新判法**：**lon/lat 逐一对（12 值）+ alt 单独判**（有则相等、无则两边都不写）；**附加快筛：无海拔点上不得出现 `,0` 结尾**（grep 即可）。
- 本条属**字段完整性**，单列台账；① 在**新判法**下仍需 PASS。

## 3. 坐标系口径（客户端强调的「先定这个再写解析器」）

1. **内部一律存 WGS84**（导出默认 `lc:crs=WGS84`）。若某条数据来源是 GCJ02，导出前先转 WGS84 再写文件，**不混着写**。
2. **导入按声明转换**：读到 `lc:crs` 就按其值转换到内部 WGS84；
   **读不到声明** → 按 WGS84 处理**并显式提示**「坐标系未知，按 WGS84 处理」。**禁止静默按某个系处理**。
3. **转换必须新写带测试的实现**，**不许复活 C 轮删掉的 `gcj2bd`/`wgs2gcj` 死代码**（那两份是死代码，语义与测试都不可用）。
4. **GCJ02 往返不可逆**：WGS84→GCJ02→WGS84 存在固有偏差，**因此往返判据只在同一坐标系（WGS84）下执行**；跨系只判「行为可解释」（有声明、有提示、不静默）。
5. **规范引用状态（如实标）**：KML `coordinates` 以 WGS84 经纬度表示属通行约定，**本轮未抓 OGC KML 规范原文**；若验收要求引用规范条文，需补抓 OGC 文档后再引用，**我不凭记忆写条号**。
6. **往返判据（审核验用）**：同一坐标系下 导出→导入→再导出，逐点比较 `coordinates`，**最大差 ≤1e-6 度**（≈0.11 m），并给出**点数**与**逐点最大差**。跨坐标系不判此项。

## 4. 离线瓦片缓存：范围与失效策略（能力交付、默认关闭）

| 项 | 规定 |
|---|---|
| **缓存键** | `(sourceId, z, x, y, version)` —— **与瓦片源解耦**，不写死任何一家；`sourceId` 由配置映射到具体源 |
| **缓存对象** | **仅已成功加载的瓦片**（被动缓存）。**不做主动批量下载/预取**：既控体积，也避免在合规未查证时放大使用 |
| **启用开关** | **默认关闭**；按 `sourceId` 白名单启用，默认白名单 **空**（见 §1） |
| **容量** | 上限 **200 MB**（可配），**LRU 淘汰**；对外暴露 `cacheBytes`（当前占用）与 `evictions`（淘汰次数） |
| **失效（2026-11-09 改判）** | **陈旧阈值默认 7 天**（可配，代码里仍叫 `ttlMs`）：只把瓦片标 `stale`，**不删数据**；**删除只走 200 MB LRU**（`evictions` 计数）；超阈值界面文案「**已缓存，但数据可能已过期（缓存超 7 天）**」，与「当前区域未缓存…」**互斥、不拼句**；联网时后台刷新；`version` 变更（源或格式升级）整批作废 |
| **未命中降级** | 条件：**断网 且 该瓦片未缓存** → 显示明确文案：**「当前区域未缓存，联网后可查看」**；**不许静默空白**，也不许伪装成加载中 |
| **诊断字段** | 需暴露 `hit`/`net`/`cacheBytes`/`evictions`（`hit` 与 `net` 已有），供验收判定「图是从缓存读的还是还在走网络」 |

**验收口径（审核验已写）**：断网后 **`hit` 递增且 `net` 不增** 才算命中缓存；`net` 仍在增长即判「仍走网络」，即使画面像缓存图。

### 4.1 ② 的三条验收项（总监 2026-11-09 定，**缺一不判 PASS**）

| # | 验收项 | 怎么判（可复跑） | 依据 |
|---|---|---|---|
| 1 | **缓存默认全关** | 冷启动读状态：`sources: []`、`items: 0`（STEP 0 已实测过一次，**本轮要在新实现上重跑确认**，不许沿用旧树读数） | 把风险面压到「用户主动开启」 |
| 2 | **来源标注全程在场**（含冷启与失败态） | ① 断网截图中可见「**数据来源：天地图 www.tianditu.gov.cn**」（或同源角注文案），**不得只剩底图**；② **冷启动首帧**与**页面加载失败/被打断**时也不得出现「审图号： 待核对」——原生初始值 `MainActivity.java:826` 目前仍是占位（页面 JS 起来后才被覆盖），归 @LC客户端 修；判据要这两张截图 | 《版权声明》「应注明来源」+ §1.4 |
| 3 | **陈旧阈值 + 过期提示**（**不是**「按天删除」） | 阈值默认 **7 天**（可配）；条件 `miss==0 && stale>0` 时出现「**已缓存，但数据可能已过期（缓存超 7 天）**」；判据只判**文案 + 出现条件 + `stale` 计数**，**不判任何「超过 N 天自动删除」**（代码无此路径，删除只由 200 MB LRU 触发，`evictions` 为证） | 《服务条款》二「对数据的及时性不作担保」+ 总监 2026-11-09 三条验收项第 3 条 |

**说明**：第 2 条只对「已启用缓存且处于离线态」的截图生效；缓存默认关时该条随 ② 一起不适用（与 §1.3 同一逻辑，避免拿不存在的界面判失败）。

## 5. 调试入口需求（给客户端，验收必需）

真机上文件选择器只能人工点，无法复现「导出→导入→再导出」，因此需要两条命令（与现有 `DebugBridge` 同一通道）：

```bash
am broadcast -a com.luopan.fengshui.DEBUG --es cmd kml-export --es path /sdcard/t.kml
am broadcast -a com.luopan.fengshui.DEBUG --es cmd kml-import --es path /sdcard/t.kml
```

要求：① 命令返回后写一行 `LCDEBUG: kml-export ok points=N path=...`；② 导入返回 `kml-import ok points=N skipped=M`；③ **不因命令暴露而放宽主 manifest 的 `exported=false`**（沿用现有动态注册 + `RECEIVER_EXPORTED` 的做法）。

## 7. 已知限制（本轮如实留档）

1. **天地图合规两段式**：门户条款**已查证·未涉及**（§1.1）；API 控制台条款**未查证**（§1.2）⇒ 缓存默认关闭、白名单为空；如日后拿到控制台条款，**只改配置、不改代码**。
2. **KML 不含样式/照片/时间动画/MultiGeometry**（最小集原则），导入遇到即跳过并计数。
3. **跨坐标系往返不判误差**（GCJ02 不可逆），只判「有声明、有提示、不静默」。
4. **触发下载/预取不做**：离线覆盖范围 = 用户实际浏览过的区域。
5. **KML 规范条文未抓原文**：文中「WGS84 经纬度」按通行约定写，若需引用规范条号须补抓后再引。
6. **`lc:created` 导入不入库**：导出侧无损，导入侧由 `GapDb.insertInterest` 取当前时间，**创建时间会变成导入时刻**；保留需改 M4 插入签名，不在本轮。
7. **缺值一律省略键**（不写 `0`、不写空串）：与 M-06 `elev=0` 同一规则——同一个坑在同一次迭代出现两次，说明「缺值用 0 顶」是通病，不是偶然。
8. **审图号未取得**（§1.4）：官网 5 条路径 0 命中 / CloudWAF 418，瓦片水印也不可达 ⇒ 角注只写「数据来源：天地图 www.tianditu.gov.cn」；**R2-032 形态判据与本结论冲突，待总监裁决**，裁决前 `map.html` 的「审图号：待核对」占位不动（我不自改他人模块、不自改已入册判据）。
