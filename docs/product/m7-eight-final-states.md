## 2. 逐条说明（只写判据里需要解释的部分）

### 2.1 第 1 条：为什么「≥5 设备 px」是判据，而不是抄 CSS 的 2px

原版是 MapLibre Marker 上的 CSS 伪元素，`2px` 是 CSS px，落到本机经 `density` 放大后才成设备 px。**验收判设备 px ≥5**；把 CSS 改成 6px 会同时放大我方线宽，属改判据凑数，禁止。

### 2.2 第 2 条：负向对照为什么算证据

`8f1ea11` 在**故意反向**的构建上跑同一套判据，得到 **10/10 FAIL**。判据能红，才能证明它在正确实现上绿是有意义的——这条与 checksheet §10 第 7 问同源：**判据不能只在能过的时候被使用**。

### 2.3 第 3 条：两个符号是**原生层**实现，不在 `map.html`

- **屏幕中心符号**：viewport 覆盖层，23 张不同位置/缩放的原版截图里圆心恒为 (614,1350) ⇒ 不随拖动/zoom/pitch 变，**所以不能画进贴地 canvas**（进去会随 zoom 缩放、随 pitch 变形，两条都与实测相反）。
- **当前位置符号**：地图坐标层，随拖动/缩放；位置由页面 `screenPointOf(lat,lng)` 投影后回传，原生只负责「把标记画在那个屏幕坐标上」。**旋转**：原版 `rotationAlignment:"map"` + `setRotation(target − bearing)` ⇒ 三角屏幕指向角 = 传入的 heading 本身，与地图 bearing 无关（逆向 `a61da79`）。
- **诚实边界**：三角相对主体的方位（上偏左 27.3°）是静态图量出来的，**bearing→朝向的动态映射**已按 `a61da79` 取证；拖图时标记按 250ms 轮询，可能滞后 1 帧（已知）；罗盘态是否显示未取证 ⇒ 不显示。
- **素材不复用**：`cross.png` 色 `#6488FC` 偏紫、52×52，与实测 `#009DFF`／114×114 不符，且主图 bundle 引用 0 次 ⇒ 按可观测像素复刻，不贴素材。

### 2.4 第 4 条：投诉行「68 vs 79」是**比较对象选错**，已按墨迹闭环

**先记我自己的错**：我 v1.0 用 dump 的节点框比了两个数（原版 `204×79` vs 我方 `200×68`），据此判「矮 11px、已知偏差下轮修」。这个判法**不成立**——原版那页根节点是 `ComposeView`，`79` 是 Compose 的**语义框**；我方是 View 的**布局框**，两者不是同一个度量。

**按墨迹复量（`6acf66d` 定案，真机 `L2E0222534833` 21:36:54）**：

```
                    原版 节点/墨迹        我方改前 节点/墨迹      我方改后（客户端口径）
问题反馈            h=79 / h=46           h=68 / h=47          墨迹 367..413 h47   顶差 0
订单投诉            h=79 / h=45           h=68 / h=46          墨迹 548..593 h46   顶差 0
```

- **字高实测只差 1px**（46 vs 47、45 vs 46），「差 11～12」是框差，不是字形差；
- 真实偏差是**墨迹位置**：改前 363/544，原版 367/548，整体偏高 4px；
- 修法：行内上下内距 `24/24 → 32/24`，**行高与步进（180）未动**，居中后下移 4px；
- 结果：**墨迹顶与原版逐值相等（差 0）**、**两行间距与原版相等**、不叠字、crash buffer 空、无 FATAL。节点框仍是 68 vs 79 —— **正常差异，不参与判定，也不去凑**。
- **绝对数必须带阈值**：同一个「墨迹顶」在不同二值化阈值下会漂 1px。阈值 150 口径：`368..412 h45` vs 原版 `368..411 h44`、间距 `180`；客户端同法得 `367..413 h47`、间距 `181`。**两套数的相对结论一致**（顶差 0、间距与原版相等、不叠字）⇒ 台账只记相对量，**绝对数一律标阈值**，否则以后复现会看到两套数以为谁错了。

**教训（同一类问题的第二次）**：这就是总监说的三种「假绿」之外的第四种——**「比较对象选错」**：判据本身能红能绿，但比的两样东西不是一回事。上一次同类是 `lc:elev`（判一个永远不会出现的字段），这次是 Compose 语义框 vs View 布局框。**判据报绿或报红前，先说清「这两个数各是什么量出来的」。**

### 2.5 第 5 条：28 张与 29 张的时点

`m6-close-summary.md:19` 里「png=29、引用↔文件 29=29」是**撤 `fig-32` 之前的时点口径**，该句已就地标注；现值为 **28=28**。凡是引旧数的文档都必须带上这个时点，否则会被读成当前值。

### 2.6 第 6 条：语义是「动作」不是「开关」

`I0(g)` 调 `g.I()`，`I()` 的 12 项里没有任何一项是 bearing/pitch/zoom/center —— 它是**一次性动作**。实测 `3d|45|106.7221|12 → 2d|0|106.7221|12|0`：只把 bearing 归零，中心和缩放一点没动。用户报的「按钮语义应为回正北」按此成立。

### 2.7 第 7 条：贴地已验，但「验到了什么」必须分清

**判据参数（签字用，缺一不可；这是可复现性的关键）**：**在 1456 空间比，不在 549 裁切空间比**——等效条件 = `translate(453.5,453.5)` + `drawImage(img,0,0,549,549)` + 默认 `imageSmoothingQuality`（实测两侧均 `low`）。基线只许用进包的 **800/q85** 五张（合计 `1,200,656 B`），1200 版仅作参考。

- **G2-A1 0.00% 是有效证据**：它证明的是**位图落点、缩放、尺寸都对**（同一 `drawImage`、同一 `translate`、同一 quality 复刻基线）。
- **G2-A2 的 0.00% 只能算「自洽」，不能算「画得像」**：环叠区基线用的是树内**同一个 `drawOutlineRings`**——等于同一函数比自己，必然 0%。它只能证明「这段代码确定性地画出了它自己」。
- **L2a 强检验本轮未做**：方案 §5 L2a 的原意是「**原生 `CompassView` 渲染 vs canvas**」，这一项留在下一轮。**不写成已验证。**
- **58.73% 那条旧结论已作废**，原因记在方法文档：在 549 裁切空间比时 `off=(1456−549)/2=453.5` 是**半像素**，裁剪原点只能取 453/454，0.5px 位移被算成「画得不像」。这是本阶段第六次「**比较对象/方式选错**」。

**结论**：用户可见行为达成（按钮按下盘面按四角投影铺在地面，不再是屏幕空间正圆），判 **已验**；但**不写「与原版 1:1」**，也不写「已证明贴地和原版盘面长得一样」。

**两条已知差、一项未做（必须同时记档）**：见 §4.4（B1 指针隐藏）、§4.5（`dialType`/`dialAlpha` 不跟随，真缺陷、下轮）、L2a（未做）。

### 2.8 第 8 条：T3 那半条为什么不是「未实现」

T1/T2/T3 三项行为都 PASS。差的是 **T3「无过渡动画」的逐帧证据**：设备无 `/system/bin/screenrecord`，静态截图判不了逐帧。按口径记「**证据不可得**」——**不写「应该没有」，也不写成「未实现」**（那是把缺证据当缺陷）。`webgl-unavailable` 同理：按代码路径登记，**未注入验证前不写已验证**。

## 4. 偏差与处置（逐条给结论，不留悬空）

### 4.1 投诉页一级两行：**已闭环**（`6acf66d`）

### 4.2 about 底部两行落点比原版低 3px

- **定性**：**已知偏差**；三条判据（两行间距差 0、间隙 37、不叠字）均 PASS，技术总监已判 PASS。

- **处置结论**：**下轮改用 `getLayout().getLineBaseline(0)`**，本冻结树不动。

### 4.3 3D「无过渡动画」逐帧证据不可得

- **定性**：**证据不可得**（设备无 `screenrecord`），与 `A-09 动效录屏` 同一口径。
- **处置结论**：不写成「没有动画」，也不写成「未实现」；关账表按「逐帧证据不可得」留档，设备具备录屏能力时补一次。

### 4.4 贴地态指针隐藏（B1，**已批准的设计差**）

- **事实**：贴地态隐藏那根竖向原生指针，只保留地面盘面。
- **依据**：原版指针是独立 DOM `<img>`、`pitchAlignment:"map"`，由 MapLibre 做地面透视；我方是原生 `ImageView` 覆盖层，**做不到贴地倾斜**。B2（悬浮不倾斜）会与盘面错位、B3（画进 canvas）会改变「指针不在盘面 canvas 内」的原版事实 ⇒ 技术总监裁定 **B1**。
- **记账**：作为「**贴地态指针隐藏**」已知可见差异记档，**不修**（不是缺陷，是已批准取舍）。

### 4.5 贴地盘面不跟随 `dialType` / `dialAlpha` 切换（**真缺陷，下轮**）

- **事实**：切换盘面类型或透明度时，贴地 canvas 上那张纹理不跟着变（读数为 `dialType:0`、`dialAlpha:1` 固定）。
- **定性**：**真缺陷**，不是设计差——用户改了盘面却看到地面盘面不变。
- **处置**：**下轮修**（贴地纹理需在 `dialType`/`dialAlpha` 变化时重建/重传），本轮不改 `map.html`（会让 M8 刚跑完的门禁与真机读数作废）。
- **当前证据载体**：`reports/M8-g2-final/g2-final-1456.txt`（`dialType:0`、`dialAlpha:1` 即该缺陷的读数现场）。
