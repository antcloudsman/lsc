- 判据（总监定）：**手指位移 (dx,dy) 与地图内容位移 (dmx,dmy) 同向=正确，反向=缺陷**

## 方法（可复跑）

1. **归零旋转**：`adb shell am broadcast -a com.luopan.fengshui.DEBUG --es cmd js --es value 'sitMode=0;bearing=0;applyTransform()'`
   —— 不清 bearing 就测，旋转会把内容位移变成斜向，符号结论会被污染。
2. **读中心**：`... --es cmd js --es value 'JSON.stringify(getState())'` → `adb logcat -d -s LCJS:V`（`LCJS: map -> {...}` 里 `lat/lng/bearing/zoom`）。
3. **手势**：`adb shell input swipe x1 y1 x2 y2 400`（地图区域中央，避开左右工具列）。
4. **内容位移换算**：地图正北朝上时
   `dmx = −Δlng × 256·2^z/360`（px），`dmy = +Δlat × 256·2^z/360 × sec(φ)`（px）；
   符号即可判定：`sign(dmx)` 与 `sign(dx)` 相同=正确，相反=缺陷。
5. **原版对照**：同一手势；原版坐标条文本随拖拽实时更新，直接读中心经纬度（`uiautomator dump` 里 `text="106.725808，26.613367"`）。

## 代码根因（`app/android/app/src/main/assets/map.html`）

```
pan(dxPx,dyPx)  :1772-1782   c.x -= dxPx/256;  c.y -= dyPx/256
触摸  :1905                  pan(-dx, -dy)       ← 传入 -fingerDelta
鼠标  :1792                  pan(lastX-clientX, lastY-clientY)  ← 同样传入 -fingerDelta
```
两次取反（调用方负号 + `pan` 内 `-=`）净效果是**内容与手指反向**。

**唯一允许的改法（总监 01:19 裁定，LC审地图 §2 证据）**：只把 `pan()` **2D 分支** `:1777-1778` 的 `c.x -= dxPx/256; c.y -= dyPx/256` 改成 `+=`。**调用方（`:1792` / `:1905`）和 `pan3D()` 一律不动**。

- 不能改调用方：`pan()` 第 2 行 `if (mode === "3d") { pan3D(dxPx,dyPx); return; }` 把**同一份实参**交给 `pan3D`；改调用方会让 2D 变对、**3D 从正确变反向**（`pan3D` 里 `mx=rx*dx*g` 语义相反）。
- 因此本条判据拆成两条独立项：
  - **2a 符号**：2D 分支 `-=`→`+=`，四方向复测全部同向；
  - **2b 逆旋转**：`bearing≠0` 时 2D 分支须先按 `-bearing` 逆旋转 `(dx,dy)` 再落经纬度（3D 的 `pan3D` 已做，2D 没做）；复测 bearing=30 下滑动内容与手指平行同向。

## 附带发现（同属第 2 条，修方向时必须一起处理）

`applyTransform()`（`:1486`）把整张地图按 `bearing` 旋转，但 `pan()` **不做逆旋转**：bearing=30° 时上滑 300 px，实测 `Δlng=0, Δlat=+0.000423`（纯竖直平移），屏幕上内容却沿 −30° 斜向移动。
**即：只要地图有旋转（坐向对齐态），修完符号仍会“斜着拖”。** 判据：修方向后，在 bearing=30 下重测，`dm` 必须与手指同向且平行于屏幕手势方向。
（注：新启动默认 `bearing=0`；我首轮测到斜向，是因为当时处于坐向态，`getState()` 读到 bearing≠0。）
