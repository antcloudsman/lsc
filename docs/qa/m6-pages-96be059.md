两种情况结论不同，所以这条**未确认**，不改判据、不写成缺陷。

### 2.5 抽屉底色：`#282D35` 反推不成立，但「原版无压暗」也不成立（2026-11-09 21:0x 二次修正）

原版 `contact.png` 与 我方 `act-contact.png` 目视对照（两张都为 1228×2700）：

```
原版   抽屉面板深、条目文字亮（156–168）；抽屉右侧地图区全亮、颜色饱和
我方   抽屉面板近黑、条目文字发灰；抽屉右侧地图区明显压暗
```

**第一步：`#282D35` 反推被否掉。** 若原版也按 0.4 压暗，原版抽屉里的文字/图标实测亮度反推原始值必须 ≤255：

```
金色图标 (168,143,98)/0.4  = (420,358,245)   R 超 255
亮字     (165,157,139)/0.4 = (412,392,348)   三通道全超 255
灰字     (156,156,156)/0.4 = (390,390,390)   全超 255
```
⇒ **原版压暗强度不可能是 0.4**，所以 `#101215 ÷ 0.4 ≈ #282D35` 这个反推不成立。

**第二步（修正我自己的上一版结论）：不能因此说「原版无压暗」。** 压暗可以是更轻的一档。用我方文字色 `#E6E6E6`(230) 当参照（`MainActivity` 抽屉条目 `Color.rgb(0xE6,0xE6,0xE6)`）：

```
原版亮字实测 156 → 156/230 = 0.68
原版金色实测 (168,143,98) ÷ 我方 (220,190,130) = 0.76 / 0.75 / 0.75
⇒ 原版压暗约 0.68–0.76（dimAmount ≈ 0.24–0.32）
我方         = 0.40（dimAmount 0.6，由 #1A1612→(10,9,7) 精确闭合）
```

**所以正确定性是：两边都压暗，我方明显偏重（0.40 vs 约 0.72）。** 反推原版抽屉面板原始色 ≈ `(16,18,21)/0.72 ≈ (22,25,29) = #16191D`（冷），与我方写死的 `#1A1612 = (26,22,18)`（暖）仍不同——**冷暖方向相反这一点与压暗无关，是底色选择差异**。

**两条实现侧结论**：
1. `contact` 弹层的压暗强度偏重：我方 `dimAmount 0.6`（透过 0.40），原版约 `0.24–0.32`（透过 0.68–0.76）；
2. 抽屉面板底色 `MainActivity:2616` = `Color.rgb(26,22,18)`（暖褐）与原版冷灰蓝不符；我方该值来自 `M3PageActivity.java:97` 的自选深色，**不是从原版量出来的**（`docs/fidelity/m6/client-four-pages-diff.md:50` 记有出处）。

**要把这两条钉死，需要原版原始色（静态可取，不必占设备）**：从原版 APK 资源里取抽屉面板/弹层压暗的真值（`LC逆向` 那条线），或在原版上补一张「抽屉打开、无弹层」截图。
在此之前：**判据不改、实现不动**——我方 0.40 已定量，原版 0.72 是**推算值（未确认）**，不能当判据用。

判据侧同前：`contact` 的 `THEME` 期望 `#101215` 量的是弹层背后的抽屉，不是联系页；应改为「弹层内底色」（两边都是纯白，白像素 64,764 vs 64,734）。
